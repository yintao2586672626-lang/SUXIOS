# 宿析试炼循环

## 触发边界

本 Skill 仅在用户明确点名 `suxi-gauntlet-loop`、试炼循环或等价的“构建者与独立盲审循环”时使用。普通功能开发、优化、复刻和产品化任务继续遵循项目默认的单主目标、最小完整闭环与按风险验证规则，不自动研究外部标杆，也不自动创建子 Agent。

## 接管目标

接收用户的自然语言目标。主动承担标杆研究、边界草案、技术路线、任务拆解、构建、判卷、返工和交付；只让用户补充建议、纠偏方向，或确认会改变真实业务/外部动作的重大边界。

## 选择执行强度

- 对多模块、新功能、产品化、复刻、明显质量提升或包含多个独立验收面的目标，执行完整试炼循环并使用实际子 Agent 隔离构建和盲审。
- 对单文件、小修复、只读状态核验等原子任务，执行紧凑循环：完成构建或检查后，切换到只看标准与产物证据的隔离判卷，再做最小验证。不要为了角色数量扩大任务。
- 用户明确要求实际子 Agent 时按要求执行。若平台无可用槽位或禁止创建，标记 `盲审未完成`，不得把主控复核伪装成独立盲审。

## 1. 建立现实标杆

主动搜索或检查与目标最接近的现实世界高水平产品、公开实现或权威标准。优先使用当前、可访问、可引用的一手证据；记录：

- 标杆名称、来源与观察日期；
- 选择理由和适用范围；
- 可实际比较的功能、流程、质量或性能维度；
- 不适用于宿析OS的部分；
- 每个决定性维度的证据获取方法。

把“高级”“3A”“行业领先”转成可观察指标。无法诚实比较时保留未知，不得凭印象宣布优于标杆。

## 2. 主动推导边界

根据目标、仓库现状、数据身份和既有授权提出边界草案，不向用户抛技术选择题。至少明确：

- 目标用户与可见入口；
- 酒店/租户、平台/来源、业务日期和指标口径；
- 允许的本地改动、保存/回读和验证范围；
- 明确非目标、失败状态和不可替代的缺失事实；
- 外部发送、生产发布、真实 OTA 写入、付费行为或不可逆动作。

最后一类动作仍须用户最终授权。只有缺失选择会改变业务模块、口径、真实对象、外部接收方或不可逆结果时，问一个决定性问题。

## 3. 拆成可判单元

将目标拆到每个单元都可独立构建、比较、判定和优化。为每个单元建立验收卡：

```text
单元目标：
专业角色：
现实标杆与证据来源：
决定性比较维度：
必须保持的底线：
实际验证方法：
边界与非目标：
通过条件：
```

若不能单独回答“通过还是未通过、依据是什么、下一处最大差距是什么”，继续拆分。

## 4. 配对构建者与盲审者

为每个非简单单元分配：

1. **专业构建者**：只负责在边界内实现该单元并产出原始证据。
2. **独立盲审者**：未参与该单元构建；每次盲审都使用不继承构建者会话的全新隔离上下文，子 Agent 使用 `fork_turns=none` 或等效新上下文，并获得明确的零写入指令。

只向盲审者传递白名单评审包：验收卡、现实标杆原始证据及来源/日期、边界、产物快照或受限只读路径、原始验证证据、固定判决协议。禁止传构建者对话、解释、计划、投入时长、自我评价、预期结论、主控代写摘要或“测试很多”等影响独立判断的信息。

盲审者必须保持执行过程零写入：禁止实际调用任何编辑、写入、`apply_patch`、提交、代修、会改变状态的命令或外部动作。主控在盲审前保存目标文件哈希和限定工作区 diff，盲审后重新计算并比较；工具轨迹仅在平台实际提供时追加核对，不作为所有环境的强制前提。发现目标文件哈希或限定工作区 diff 发生变化时，标记 `盲审未完成` 且不得输出判决；哈希与 diff 一致且未观察到写入时允许正常判卷。仅仅工具可用但未调用不导致失败。并发槽位有限时串行复用角色；共享文件、OTA 采集核心、鉴权、多租户、数据库迁移、收益公式和生产状态不得并行写入。构建者子 Agent 不提交 Git，由主控统一审查和验证。

## 5. 盲审与打回

盲审者按固定格式输出：

```text
判决：PASS | FAIL | BENCHMARK_MISSING
流程状态：正常 | 盲审未完成 | 外部权限阻塞
现实标杆证据：
产物证据：
逐维比较：
当前最大差距：
最小返工范围：
复验方法：
```

判决只能是 `PASS`、`FAIL` 或 `BENCHMARK_MISSING`：

- 只在预先声明的决定性维度上有证据优于现实标杆，且真实性、兼容性、核心功能和授权边界没有退步时判 `PASS`。
- 构建者自称完成、主观相似、只有单元测试、只有界面、只有构建者自述，或产物证据未达到标杆时判 `FAIL`。
- 缺少现实世界标杆或缺少可比证据时必须判 `BENCHMARK_MISSING`，不得用内部感觉、构建者结论或不可复现的印象补位。

登录、权限、凭证、外部服务等阻塞只作为独立流程状态报告，不新增第四种判决。若隔离上下文或严格只读无法保证，则流程状态为 `盲审未完成` 且不得输出任何判决。

打回时每轮只修最大的可验证差距，并沿用同一标杆、口径和验证方法复验。若标杆事实发生变化，先显式更新验收卡。连续三轮没有新增决定性证据时，停止试炼并报告唯一真实阻塞；不得降低标准、替换口径或虚构胜出。

## 6. 集成与总盲审

所有单元通过后由主控集成。安排未参与构建的总盲审者，从真实用户入口执行端到端任务，并检查：

- 各单元组合后仍达到标杆；
- 用户能找到、操作并得到目标结果；
- 需要持久化时可保存并精确回读；
- 来源、酒店、平台、日期、口径和失败状态真实；
- 没有因局部优化破坏兼容性或下游链路；
- 外部/生产/不可逆动作未越过用户授权。

只有所有单元和端到端总盲审都通过才报告完成。最终输出分别列出：标杆与来源、已通过单元、端到端证据、未验证项、外部阻塞和剩余风险。
