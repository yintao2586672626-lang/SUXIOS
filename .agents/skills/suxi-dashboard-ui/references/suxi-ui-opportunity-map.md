> 核对日期：2026-07-30
>
> 证据范围：企业微信推送、自动化运行监控、PMS经营数据、门店管理、今日经营工作台及相关前端运行函数。这里的“未发现”只表示本次范围内未发现，不代表整个项目永久没有。

## 使用方法

先检查当前页面，不按术语数量评价页面。将候选分为四类：

- `已有`：当前页面已经具备，不重复实现。
- `局部`：已有基础，但真实问题仍缺一段交互。
- `候选`：能解决当前用户问题时再实现。
- `不适合`：与酒店经营后台当前任务无关，不因 VibeHub 收录就引入。

一次页面优化通常只选一项最高价值候选。实现后仍以真实数据、保存回读、失败状态、移动端和当前用户目标验收。

## 对三源稳定传送的组合

三源稳定传送适合使用 `User Flow + State + Timeline`：

```text
选择门店、业务日和来源
-> 读取真实数据
-> 保存并数据库回读
-> 生成企业微信消息预览
-> 授权目标测试发送并取得回执
-> 启用固定时间计划
```

每一步显示当前状态、失败原因和下一步动作。流程或步骤高亮不等于成功；真实送达仍以企业微信回执为准，定时启用仍以实际计划与调度状态为准。

## 不优先吸收

- `Carousel`、`Rate`、`ColorPicker`、`Pricing`、`SocialProof` 等面向内容站或营销页的模式，不进入当前经营后台。
- 全站深色模式、持续动画、弹性回弹和大面积渐变不是当前功能缺口。
- `Breadcrumb` 只有在真实路由层级变深时才使用；当前单页切换不为形式增加层级。
- VibeHub 的练习、解锁和复制安装能力不进入酒店日常操作页。

## 代表性判断样例

- “看到 VibeHub 有 Drawer，监控页是不是也该加” → 先保留已有直接穿透；只有明确需要原页轻量查看且不会复制完整页面时才考虑 `Drawer`。
- “酒店越来越多，每次拉下拉框找半天” → 优先可搜索 `Select` 或 `AutoComplete`。
- “这次为什么没发出去，我想看卡在哪一步” → 保留历史表格，给单条记录增加 `Timeline`。
- “页面加载时一片空白，过几秒突然全出来” → 可使用 `Skeleton`；失败后必须切到真实错误。
- “页面太复杂” → 先删除重复信息；只有低频但仍必要的内容才进入 `Collapse`。
