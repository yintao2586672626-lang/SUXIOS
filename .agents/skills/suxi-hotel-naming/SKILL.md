# 酒店与房型命名优化

## 目标

基于已确认或在材料中清晰可见的事实，生成易理解、可区分、可检索且便于转化测试的酒店门店名或房型名。名称是信息表达工具，不把命名本身写成已证实的转化提升。

## 工作流

1. 先判断对象是 `hotel_store`（酒店/民宿/门店）还是 `room_type`（房型）。若两者都有，分开输出，不能共用同一套层级。
2. 从用户描述、表格或截图提取事实，并明确分成：已确认事实、合理候选、未知项。
3. 只把已确认事实写进推荐名。截图模糊、被遮挡或无法辨认的内容保持未知。
4. 按对应规则生成候选：
   - 房型命名读取 [references/room-type-naming.md](references/room-type-naming.md)。
   - 酒店/门店命名读取 [references/hotel-store-naming.md](references/hotel-store-naming.md)。
5. 对候选评分并淘汰歧义名：清晰度 25、事实支撑 25、需求匹配 20、差异化 15、简洁度 10、层级一致性 5。
6. 输出一个首选、3–5 个备选、依据、风险/待确认项和验证建议。

## 不可突破的事实边界

- 不编造设施、面积、床型、景观、位置、楼层、客群、装修风格、星级、评分或品牌背书。
- 未核验时，不声称商标可注册、平台审核一定通过或名称符合某个平台最新规则。
- 不用“至尊、奢华、私汤、海景、智能、亲子、行政”等词暗示不存在或未确认的权益。
- 诗意前缀不能代替标准品类。房型至少保留“大床房、双床房、家庭房、套房”等可识别后缀。
- 同义词堆叠、纯情绪词和无法区分权益的等级词只作为低优先级候选。
- 没有对照实验时，不给出确定的转化提升百分比，也不把相关性写成因果。
- 本 Skill 只生成和评估名称，不自动修改 OTA、PMS、门店资料或生产数据。

## 截图处理

- 逐项记录截图中可读的原名称、标签、房型、设施、景观和层级；说明每条依据来自哪个可见区域。
- 对无法读取的字段标记“截图未确认”，不要用常识补齐。
- 同时给出“保守优化版”和“同风格相似版”。相似版只借鉴结构、节奏和语气，不复制未经证实的卖点。
- 若截图展示多个房型，先检查层级冲突、重复词和同义名，再逐项优化。

## 输出格式

```markdown
对象：门店名 / 房型名

首选名称：...
命名依据：已确认事实 ...

备选：
1. ... — 适用侧重点
2. ... — 适用侧重点
3. ... — 适用侧重点

评分：清晰度 / 事实支撑 / 需求匹配 / 差异化 / 简洁度 / 层级一致性
待确认：...
验证建议：...
```

验证名称效果时，优先做同房型、同价位、同流量来源和相近日期的受控测试，观察曝光到详情点击率、详情到预订转化率、房型售卖占比、取消率和每千次曝光收入。命名是变量之一，不替代图片、价格、点评、权益和库存的影响分析。
