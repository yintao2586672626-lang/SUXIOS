# 酒店与门店命名参考

## 命名任务

门店名解决“这是什么、在哪里、适合谁、有什么记忆点”；房型名解决“我将住进什么空间、核心差异是什么”。两者必须分开设计。

## 事实输入

至少梳理以下信息，缺少时明确标记未知：

- 品牌或主名称是否已经确定。
- 真实地理位置、商圈、交通枢纽或景点关系。
- 业态：酒店、民宿、客栈、公寓、度假酒店等。
- 核心客群：商务、亲子、度假、长住等。
- 可兑现的核心卖点与风格。
- 名称是否需要承接既有口碑、品牌资产或连锁规范。

## 推荐结构

优先采用易识别的结构：

- `品牌锚点 + 已确认地点/商圈 + 品类`
- `记忆词 + 已确认场景/景观 + 品类`
- `品牌锚点 + 核心定位 + 品类`

名称建议保留一个清晰主锚点，避免同时塞入多个景点、商圈、风格和客群。地点词只有在位置关系真实、不会误导距离时才能使用。

## 候选评价

- 看一眼能否知道它是酒店、民宿还是其他业态。
- 是否能从同商圈同类门店中区分出来。
- 是否容易读、说、输入和记忆。
- 是否与实际位置、产品和客群一致。
- 是否能自然延展到房型、视觉和文案体系。

商标、工商名称、平台重名、禁限词和品牌授权必须另行核验。未经查询，只能写“待核验”，不能承诺可注册或可上线。

## 截图优化

收到截图时，先提取可见名称、品类后缀、地点词、卖点词和同屏竞品结构；无法辨认的内容保持未知。输出两组：

1. 保守优化版：最大限度保留原有识别资产，只修复冗长、歧义和顺序问题。
2. 同风格相似版：借鉴名称结构和语气，使用用户已确认的自身事实，不复制他店品牌或未经证实的卖点。

## 效果验证

命名效果需要实验，不从词感直接推断。尽量保持图片、价格、库存、权益和流量来源不变，对比：

- 曝光到详情点击率。
- 详情到预订转化率。
- 目标房型售卖占比。
- 取消率与投诉/预期落差。
- 每千次曝光收入。

数据不足时只报告方向性判断，不给确定提升百分比。
