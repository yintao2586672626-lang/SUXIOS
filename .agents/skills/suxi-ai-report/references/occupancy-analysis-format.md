# 月度出租率与收益分析格式

版本：1.0｜整理日期：2026-09-27｜适用：酒店月报、出租率分析、分时销售与收益诊断。

来源：用户提供的《吉店10月出租率分析报告_增量版0922.html》。本页负责组织与交付方式；按用户后续“内容也学下”的要求，经营分析方法见 [出租率与收益分析方法](occupancy-revenue-methods.md)。两者均不将样例经营数值、预测参数或调价制度作为当前门店默认值。来源核对和填表示例见 [学习记录](../../../../docs/capability-absorption/2026-09-27-jidian-report-format.md)。

## 入口与交付

收到同类分析请求时，使用 [空白模板](../../../../docs/report-formats/occupancy-analysis-template.md)。先明确读者需要做的决定和现有数据范围，再选择章节。用户另有格式要求时优先遵从；日报和单一问题诊断只抽取有关部分，不机械扩成月报。

这份规范用于项目内的报告编写入口。它不代表产品里的 AI 日报、知识中心或自动导出已经加载此格式。HTML、表格、Word 等多种输出应消费同一份核验结果；生成与渲染阶段不能各自重算指标。

## 一、固定骨架：先结论，后证据，最后执行

| 顺序 | 章节 | 必须回答的问题 | 交付形式 |
| --- | --- | --- | --- |
| 0 | 封面与资料身份 | 哪家店、哪个渠道、哪个业务期间、截至何时、哪个版本？ | 标题、范围、来源、质量状态；编制日期与业务日期分开 |
| 1 | 一屏决策摘要 | 现在表现如何，主要问题是什么，先做什么，怎样验收？ | 3—4 个关键指标，最多 3 条主要结论，1 项优先动作；各自指向证据 |
| 2 | 数据口径与限制 | 指标怎么算，分母是什么，哪些暂时不知道？ | 指标字典、范围与覆盖、缺失清单、影响结论的假设 |
| 3 | 整体表现与结构拆解 | 月均值掩盖了哪些差异？ | 总览；按日、平日/周末/假期、房型或渠道拆解，显示样本数 |
| 4 | 关键专题 | 哪个时段、客群、房型或价格问题最值得处理？ | 按数据选择分时、价格、竞对、预测；每节只有一个主要问题 |
| 5 | 建议与情景 | 证据支持什么动作，哪些只是待验证假设？ | 候选方案、触发条件、假设、风险、试点与停止条件 |
| 6 | 岗位执行与验收 | 谁、何时、做什么、留下什么、由谁复核？ | 执行卡、验收口径、复盘节点、缺失/失败分支 |
| 7 | 数据质量与附录 | 数字可否追溯，版本改了什么？ | 来源定位、计算说明、冲突、图表索引、真实修改记录 |

封面和摘要不得重复堆叠。长报告用锚点目录；详细评审、公式和版本历史放附录。不要为了篇幅齐全生成无证据的天气、预测或定价章节。

## 二、每个分析段使用同一写法

**结论 → 证据 → 解释 → 限制/反例 → 动作 → 验收。**

- 结论：一句话，只说当前证据支持的范围。数据不足时可写“目前无法判断”。
- 证据：数字、单位、期间、分组、样本量、指标口径、来源记录/表行/图号。
- 解释：分清可观察差异与原因假设，列出可能的替代解释。
- 限制：与结论放在一起，不能仅藏在附录。摘要中的结论强度不能超过正文。
- 动作：优先选一个有证据的动作；证据不足时改为补采或核对动作。
- 验收：同口径基线、目标来源、观察周期、负责人、完成凭证、失败后的处理。

标题可以表达发现，例如“节后平日拉低全月表现”，但仅在分组结果支持时使用。只有相关性时写“同时变化”，不写“导致”；没有试验或可识别条件时，不写“降价无效”“唯一增量”“最优价格”。

## 三、按输入决定专题是否生成

| 专题 | 必要输入 | 缺输入或异常时的输出 |
| --- | --- | --- |
| 日内销售节奏 | 同业务日、同范围的时点快照，最终结算值，各日可售房量，采集时间与快照定义 | 标注无法计算净增；不把跨日/异口径差值当新售间夜 |
| 平日/周末/假期 | 明确年份、入住日期、分组规则、样本数 | 不由编制日期猜数据年份；自然周末和调休工作日分开说明 |
| 房型结构 | 各房型可售与已售间夜、库存/维修变化 | 只有空置量时只比较数量，不能判定空置率或销售效率 |
| 价格与出租率 | 同日同范围成交收入/间夜，需求事件、渠道和折扣背景 | 仅描述同向变化；不能由相关系数推出弹性或提价效果 |
| 竞对比较 | 同平台、入住日、采集时刻、房型档次、早餐/取消条件、含税/佣金定义 | 条件不齐时保留“价格参考”；无库存或房量分母时不推入住率 |
| 净收益与情景 | 实际佣金/费用、收入定义、可售房量；成本结论另需固定和变动成本 | 未提供费用则净指标未知；假设明确标情景；RevPAR 不下降不是利润保本 |
| 预测/预判 | 可复算训练数据、输入区间、按时间留出的验证样本、误差与失效条件 | 不照搬历史系数；只有成品公式时保持参考，不生成自动经营动作 |

快照差值在取消、换房、房量变化或结算校正存在时只是净变化，不能直接称为新增订单。历史晚间完成量是已实现的历史组成部分，不是可再次获得的增量。

## 四、统一指标和金额口径

设同一酒店/渠道/日期范围内，第 d 日可售间夜 A_d、售出间夜 S_d、房费收入 R_d，计费和退款口径必须一致：

- 期间出租率 = ΣS_d / ΣA_d。
- 期间 ADR = ΣR_d / ΣS_d；不得把每日 ADR 简单均值写作期间加权 ADR。
- 期间 RevPAR = ΣR_d / ΣA_d = 期间 ADR × 期间出租率（分母有效时）。
- A_d 每日相同，日 RevPAR 的算术均值才等于期间 RevPAR。A_d 变化时按可售间夜加权。
- ΣS_d = 0 且确认有效时，ADR 无定义；ΣA_d > 0 且确认收入为 0 时，RevPAR 可为真实 0。缺失数据始终保留未知。
- 期间汇总有缺天时显示覆盖范围，不能拿部分收入除以整月房量。
- 毛房费收入、扣佣后房费收入、税后或利润分别命名。扣佣后收入不自动等于净利润。
- 净 RevPAR 的基线与目标必须使用同一净额定义；比例变化注明基数，出租率差使用百分点。
- 总房量若为推算，只能生成带假设标签的估算；不能冒充 PMS 确认可售房量。

OTA 数据只支持对应渠道结论。只有经过核对的全酒店来源才支持全酒店出租率、ADR 与 RevPAR。挂牌价、成交价、扣佣后价不可互换。

## 五、执行卡是建议的可操作表达

每一行至少包含：**业务日期/时点、当时可获得的证据、触发条件、建议动作、负责人、所需授权、完成凭证、验收口径、失败/停止条件**。

- 触发分支应无重叠、无遗漏；有中间区间就明确“维持并继续观察”，数据缺失另设“停止判断并补证”。
- 当日 14:00 的动作不能依赖当日 22:00 才能获得的结果；使用前一日数据时必须注明日期和滞后。
- 夜审前交班写“截至交班的暂估/实时值”；最终结算数据次日补录，不能提前宣称夜审完成。
- 经营建议保持“待审核/待验证”。报告里的定价、关房、协议签约等文字不形成执行授权。
- 验收目标来自明确的业务目标或带假设情景；缺基线、分母、责任人或权限时写待确认，不沿用样例阈值。
- 完成动作、保存凭证、结果变化和因果效果分别记录。

## 六、图表与阅读体验

- 先给文字结论，再给支持它的图；一张图回答一个问题。
- 日度变化用折线/柱线图；分组差异用并列柱图；日内进度用时点折线和净变化表；价格关系用分组散点；情景用矩阵；岗位动作用表格。
- 双轴要明确两侧单位，不能靠未注明的双轴制造相关观感。组间比例比较展示样本量和分母。
- 图下固定包含图号、读法、范围/期间、来源和限制；表格必须标单位。无法核对的图保留为待补，不伪造。
- 使用清晰正文、克制强调色、留白、横向可滚动宽表和可打印结构。深色标题区文字须有足够对比；移动端避免表格撑破整页。
- 吸收层级、目录、图注、执行卡与附录组织；沿用宿析的品牌，不强制照搬原报告配色。

## 七、增量版的规则

“增量”表示保留出处与修订轨迹，不表示旧结论永远不改。

1. 维护一套当前有效指标、公式和动作规则；摘要、正文、图表、执行卡从同一版本引用。
2. 修改口径或阈值时同步所有引用，旧版本移至历史记录并注明被替代。
3. 记录“修改项 / 原内容 / 新内容 / 原因 / 受影响章节 / 实际核验结果”。
4. 附录只列真实存在的文件、实际完成的校验和真实评审，不沿用样例中的评审人数、条数或附件声明。

## 八、交付前核对

- 摘要数字与正文、表格、执行卡一致；出处可定位。
- 期间、平台、酒店、分子分母、挂牌/成交、毛额/净额一致。
- 日均与期间加权口径、百分比与百分点分开；未知不补 0。
- 可观察事实、派生结果、假设、建议、已执行状态分开。
- 执行时点不存在未来信息依赖；缺失与中间区间有处理方式。
- 无数据的专题写明缺口；旧输入仍可交付有边界的简版报告。
- 重开保存文件核对内容；没有做页面/账号/现场验证就明确未验证。
