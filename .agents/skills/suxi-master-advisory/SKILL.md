# 宿析OS 165 视角顾问与执行

## 目标

把用户提供的 165 份人物视角材料作为可追溯的问题框架，而不是 165 个人格、权威投票或真人背书。顾问阶段发现最大盲点；执行阶段由 Codex 对宿析OS代码、数据合同和实际页面负责，完成可验证闭环。

来源指纹与处置边界见 [`docs/knowledge/master-perspectives/source-manifest.json`](../../../docs/knowledge/master-perspectives/source-manifest.json)。当前已审查外层包 SHA-256 为 `32c06de45983119efd6f7cfa9b1e8ca5ce59f8a4e5339267dc383a5fc0ee3970`；重复包不重新安装、解压或执行。视角目录以 [`app/service/MasterPerspectiveAdvisoryCatalog.php`](../../../app/service/MasterPerspectiveAdvisoryCatalog.php) 为当前权威合同。

## 模式

- 用户只要顾问、审查、判断或方案：使用 `advisory`，保持只读，不修改代码或业务数据。
- 用户说执行、实现、修复、继续打磨或做进系统：使用 `delivery`，完成最小但真实的入口、动作、保存/产出、回读和失败状态；顾问结论不能替代实现。
- 用户只点名某位人物：只使用目录中有来源记录的可复述方法问题；目录缺失时标为候选，不编造该人物观点、语气或引语。

## 选择顾问视角

每题选择 2 至 5 个领域视角，按问题和证据缺口选择，不按名气或数量投票：

1. 默认包含“证据与不确定性”和“客户与价值”。
2. 竞品、渠道、定价或资源取舍加入“竞争与战略”。
3. 流程、负责人、SOP 或落地加入“运营与执行”。
4. 不可逆动作、成本、投资、审批或高不确定性加入“风险与韧性”。
5. 团队、客诉、培训或跨部门加入“沟通与协同”。
6. 员工评价、隐私、权限、客群差异或跨酒店使用加入“伦理与公平”。

不并行召唤 165 个角色，不把同一模型的多次输出写成独立专家共识。需要并行工程工作时，只按真实代码依赖和文件边界拆分，不按人物数量拆分。

## 顾问合同

先锁定目标用户、酒店/租户、平台/来源、业务日期、指标口径、事实质量、保存与回读状态。当前事实、派生指标、视角假设、未知和用户决定必须分开。

每个选中视角只输出：

- 它要检查的关键问题；
- 支持证据与冲突证据；
- 仍缺什么；
- 哪条观察会推翻当前判断；
- 对一个最小下一步的影响。

最后保留一致项和分歧项，只推荐一个最高价值的下一步。人物材料不补造酒店、OTA、PMS、收益或客户事实；渠道事实不扩大为全酒店事实；观点数量不构成证据。

## 执行合同

在 `delivery` 模式下：

1. 从真实业务问题和产品链定位一个最高价值断点。
2. 检查当前工作树和目标文件差异，复用现有入口与服务，保护并发修改。
3. 把顾问意见转成可证伪的实现合同，而不是页面上的人物聊天或长篇报告。
4. 实现用户可找到、可操作、可保存/产出、可回读的最小闭环；缺失与失败状态必须可见。
5. 至少验证一个正常样例和一个缺失、失败或不应执行的反例；页面变更尽可能打开实际页面。
6. 报告实现、本地/单元/集成、GitHub、部署、账号/现场和经营结果各自证据层，不互相冒充。

顾问团没有自动调价、改库存、写 OTA/PMS、发送消息、审批、发布、提交、推送或部署权限。外部动作仍由用户主动触发并遵守当前任务授权。

## 完成条件

`advisory` 完成需要：来源边界清楚、2至5个视角有问题相关性、事实与假设分开、冲突和可证伪条件可见、只有一个最高价值下一步。

`delivery` 完成还需要：建议已进入宿析OS真实入口或当前代码路径，核心动作可运行，需要持久化时保存与精确回读已验证，失败状态未被掩盖，最小回归通过。只生成顾问报告、计划、Skill、卡片或 Demo 不算执行完成。
