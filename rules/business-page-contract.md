# 宿析OS经营页面合同 v1

## 1. 目的与适用范围

本合同用于把 OTA 数据、收益分析、运营管理和投决页面的接口、状态、展示、下载与验证闭合为同一条可核对链路，防止字段漂移、口径错位、页面与导出不一致，以及缺失数据被包装成成功。

在新增或修改以下任一对象时适用：

- OTA、收益、运营、投决等数据密集页面；
- 页面依赖的接口字段、类型、指标公式或响应状态；
- 页面卡片、表格、图表、下载、图片、CSV/XLSX 导出；
- 会影响事实放行、AI输入或运营动作依据的数据质量状态。

纯文案、孤立静态样式或不改变数据合同的小改，只执行与改动直接相关的视觉和回归检查，不机械套用全部条目。

## 2. 严格级别

### 2.1 硬门禁：被改链路必须通过

1. **范围身份**：根据业务实际固定并回显 `tenant_id`、`system_hotel_id`、`platform`、平台门店标识、`business_date` 或日期范围、`source_method`、`collected_at`、`schema_version` 和数据质量状态。非 OTA 页面可省略不适用字段，但不得省略酒店、日期、来源或指标范围等决定事实身份的字段。
2. **响应合同**：新接口和本次被修改的接口使用项目标准 `code/message/data`；需要放行经营事实时同时返回证据元数据。HTTP 状态、业务 `code`、错误信息和数据状态不得互相矛盾。
3. **状态合同**：请求成功与数据可信分开。按实际路径使用 `loading`、`ready`、`empty`、`partial`、`stale`、`unverified`、`blocked`、`error`；保存或执行动作的成功状态另行表达，不能覆盖数据质量状态。
4. **同源展示**：页面卡片、表格、图表与下载/导出复用同一 ViewModel、列定义、格式化函数、顺序和缺失状态，或通过自动化测试证明映射完全一致。禁止维护一份无人校验的独立导出字段表。
5. **真实失败**：缺字段、采集失败、来源不匹配、日期不匹配、权限不足和登录阻塞必须可观察；不得用 `0`、空数组、旧数据、缓存、其他门店数据或宽泛成功提示补位。
6. **聚焦验证**：至少覆盖一个代表性正常样例和一个关键缺失、部分或失败样例；需要保存时验证正式保存与精确回读。静态合同、本地页面、真实账号、生产部署和经营效果分层报告。

### 2.2 条件门禁：触发时必须执行

1. 修改页面样式或信息层级时，优先复用现有语义 Token；只在缺少业务语义时新增品牌、状态、成本、利润等 Token，不复制新的整套主题。
2. 修改前端或交互时，运行目标页面实际检查或现有视觉冒烟；稳定且高价值的关键页面/状态才增加截图基线。
3. 真实接口尚未完成时可用 Mock/fixture 验证 UI 状态，但必须标记为 `synthetic`、`mock` 或 `test-only`，且成功、空、部分/缺失、错误状态与真实证据分开。
4. 视口按用户真实设备和风险选择。默认优先主桌面视口与一个窄屏视口；只有已有真实设备覆盖需求时才扩展为六视口或更大矩阵。

### 2.3 非默认阻塞项

- 不要求一次性迁移所有历史 `code=0/msg` 或直接 `json()` 响应；只约束新接口与本次被修改的接口，并保留兼容适配。
- 不要求为每个页面建设通用 Mock 服务、像素级基线或六视口全状态矩阵。
- 不因 Token 整理、全局响应重构或视觉基线治理推迟已经可验证的核心业务闭环。

### 2.4 现有页面覆盖登记

现有产品链页面由 `rules/business-page-contract-registry.json` 统一登记，并以
`resources/frontend/templates/manifest.json` 为页面片段事实源。登记表绑定页面片段、范围维度、状态要求、源码锚点、现有回归和证据上限：

- **域先分类**：模板 manifest 的每个 domain 必须明确纳入或写明排除理由及替代门禁；新增未分类 domain 时失败关闭；
- **active + strict**：当前可用的 OTA、数据健康、收益、运营、AI 工作台和高级 AI 工具箱入口，必须保留酒店、业务日期、来源、事实状态、失败可见性及聚焦回归；
- **继承片段**：只负责页面容器、闭合或辅助配置时，可继承父页面合同，但必须登记片段和继承理由；
- **frozen_hidden + baseline**：阶段一冻结隐藏的投决、生命周期入口只维持诚实内容与隐藏边界，不冒充可发现、可操作或已现场验证；
- **失败关闭**：新增核心片段未登记时门禁失败；删除、改名或移除登记源码标记和回归证据也会失败；登记的回归文件由专用验证器实际执行，不只搜索测试标题。

登记表只约束当前代码事实及其回归证据。它不会把静态检查升级为真实账号、正式保存回读、生产或 `field_validated` 证据。

## 3. 推荐响应与证据元数据

```json
{
  "code": 200,
  "message": "ok",
  "data": {},
  "meta": {
    "schema_version": "business-page.v1",
    "tenant_id": 1,
    "system_hotel_id": 1,
    "platform": "ctrip",
    "platform_store_id": "example-store",
    "business_date": "2026-08-22",
    "source_method": "authorized_source",
    "collected_at": "2026-08-22T08:00:00+08:00",
    "data_status": "ready"
  }
}
```

示例只定义结构，不是线上酒店、门店、日期或来源事实。接口可以按现有兼容边界把 `meta` 放在 `data.meta`，但同一接口版本内位置必须稳定，前端不得猜测多个位置后静默放行。

## 4. 页面状态语义

| 状态 | 含义 | 页面行为 |
|---|---|---|
| `loading` | 当前范围正在请求 | 保留范围信息，禁止显示旧范围为当前结果 |
| `ready` | 当前范围事实通过所需校验 | 展示数据、来源、日期和必要操作 |
| `empty` | 来源确认当前范围确实无记录 | 明确“确认为空”，不得显示为 0 业绩 |
| `partial` | 只有部分来源、字段或日期完成 | 展示已有部分和缺口，限制下游结论 |
| `stale` | 证据超过当前允许时效 | 展示历史时间，不冒充当前事实 |
| `unverified` | 存在数据但身份、口径或回读未完全验证 | 仅作参考，不进入需要真实事实的下游 |
| `blocked` | 登录、权限、绑定或必要证据阻塞 | 显示准确下一步，不自动绕过 |
| `error` | 请求、解析、保存或回读失败 | 显示真实失败阶段和可重试边界 |

## 5. 黄金样例与验证

当前黄金样例是携程 eBooking 的展示/下载同源路径：

```text
ctripSummaryDisplayCards
  + ctripDownloadRows
  + ctripEarlyMorningSourceNotice
  -> buildCtripBusinessCanvas
  -> ctrip_channel_order_breakdown.test.mjs
```

该样例只证明当前代码级页面/下载合同，不证明真实账号点击、线上部署或现场数据正确。执行：

```powershell
npm.cmd run verify:business-page-contract
```

该命令运行登记表合同测试，并自动收集、执行所有 surface 的 `regression_checks`。普通展示文案不作为默认硬锚点；只有“不采集、不写业务数据、不自动审批”等事实或授权边界文案可以设为硬门禁。

## 6. 停止条件

被改页面完成硬门禁、适用的条件门禁和最小回归后停止。历史全量响应迁移、全主题重构、通用 Mock 平台与全页面六视口基线另行立项，不在普通功能内扩张。
