# Codex 执行与状态模子

这是宿析OS日常开发的单一执行与汇报口径。其他规则出现重复或冲突时，本文件优先决定任务怎么推进、怎么验证、怎么报告；业务真实性、权限和数据安全边界仍按专项规则执行。

## 1. 执行模子

```text
一个目标 → 最小改动 → 对应验证 → 明确状态 → 停止
```

1. 每轮只推进一个可验收结果；先确定范围、非目标、验收和停止条件。
2. 分析、调研、方案、初稿、评审或测试只有在结果会改变决定时才做。
3. 实现最短可用闭环；不自动扩成全仓扫描、多个候选或下一阶段。
4. 验证通过后立即报告并停止；没有新风险时不重复读取、测试或审查。

## 2. 验证模子

- **简单修改**：对应模块测试 + 必要语法或类型检查。
- **复杂修改**：涉及模块测试 + 直接依赖模块测试。
- **大型/核心重构**：才运行一次完整测试套件。
- commit、PR、发布候选、文件数量或“重要”标签本身不升级验证等级。
- 同一未变化产物复用已有证据；伞形命令覆盖的子检查不重复运行。失败后只复验失败项、修改项和直接依赖，除非影响面扩大。
- 测试、页面/API、保存回读、GitHub、部署和现场结果是不同证据，不能互相冒充。

## 3. 状态模子

涉及修改时必须给出一行状态，不再只说“完成”：

```text
状态：实现<状态>｜验证<状态>｜Git<状态>｜部署/现场<状态>｜阻塞<状态>
```

允许值：

- 实现：`无修改`、`已修改`。
- 验证：`未验证`、`聚焦通过`、`集成通过`、`现场通过`、`失败`。
- Git：`不适用`、`未提交`、`已提交未推送`、`已推送`。
- 部署/现场：`不适用`、`未部署`、`已部署未现场验证`、`现场已验证`。
- 阻塞：`无`，或一个真实阻塞；未知就写 `未知`。

示例：

```text
状态：实现已修改｜验证聚焦通过｜Git未提交｜部署/现场未部署｜阻塞无
```

## 4. 默认回复模子

除非用户明确要求详细版，修改任务最终只输出：

```text
结果：一句话说明用户现在得到什么
状态：实现…｜验证…｜Git…｜部署/现场…｜阻塞…
改动：只列当前任务的关键改动
验证：只列实际运行及其结果；未运行不写成计划
下一步：唯一下一步；当前闭环结束则写“停止”
```

默认控制在 8 行内。过程更新只说新证据、真实阻塞或下一动作，不重复背景、计划和已经报告过的内容。

## 5. 项目修改总账模子

盘点整个项目时先只读，不清理、不重置、不提交。按业务目标分组，不按每个文件堆清单：

| 修改组 | 来源/负责人 | 实现 | 验证 | Git | 部署/现场 | 唯一下一步 |
|---|---|---|---|---|---|---|

- 来源只使用：`当前任务`、`用户已有`、`并发任务`、`历史遗留`、`未知`。
- 没有当前证据就写 `未知`，不得从文件存在、测试通过或 HTTP 200 推断提交、部署或现场完成。
- 总账只回答“现在在哪一层、还差哪一步”；过程日志、完整 diff 和测试清单按需展开。
