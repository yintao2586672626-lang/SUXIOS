# 携程 / 美团字段全量采集与数据地图

## 1. 结论

当前代码并不是“完全没有字段体系”，而是两端成熟度不一致：

- 携程已有 19 个业务模块、79 个接口目录、278 个唯一指标、5,169 个来源别名，接口和字段目录较完整。
- 美团已有流量、订单、同行排名、搜索词、预测、流失订单等归一化能力，但缺少和携程同等级的 `接口 → 字段 → 来源路径 → 存储 → 回读 → 页面用途 → 状态` 总目录。
- 两端统一的主存储是 `online_daily_data`，原始记录由 `platform_data_raw_records` 保留，字段级事实位于 `online_daily_data.raw_data.field_facts`。
- 字段目录通过不等于真实业务可用。只有来源、账户/门店绑定、目标日期、采集轨迹、保存、数据库回读和字段状态全部成立，字段才可被标记为可用。

本次新增的数据地图是代码合同，不是一次真实采集报告；未登录携程/美团，未写真实数据库，也未把目录存在冒充为目标日数据可用。

## 2. 统一事实链

每个字段必须能追到以下链路：

`平台 → 账户/门店 → 目标日期 → 接口/来源键 → 原始记录 → 标准字段/字段事实 → 数据库回读 → 页面用途 → 当前状态`

统一状态规则：

- `captured`：真实响应命中且值存在。
- `field_missing`：接口命中但字段不存在。
- `api_not_hit`：目标接口未命中。
- `parse_failed`：接口命中但解析失败。
- `persistence_failed`：解析成功但保存失败。
- `readback_failed`：保存后无法按门店、日期、来源和任务精确回读。
- `unverified`：只有目录或代码合同，尚未用真实响应证明。

任何缺失都不能用 `0`、空数组、旧日期数据或默认值代替。OTA 字段只代表 OTA 渠道，不自动扩大为全酒店经营事实。

## 5. 已确认的真实缺口

### 已收口：携程专用事实表是主存储的只读投影

当前事实仍只先写入并按精确身份回读 `online_daily_data.raw_data.field_facts`。`CtripMetricFactProjectionService` 仅在主表保存和回读成功后，把已验证字段投影到 `ota_ctrip_metric_facts`，不创建第二条采集或事实来源。

影响：专用表仅供既有查询兼容；主表回读失败时不会投影，也不能以投影表反向宣称采集成功。

验证：字段地图验证器会同时确认投影表写入存在，且调用位置位于主表保存/回读之后；否则仍显示该缺口。

### P2：美团接口级目录待真实响应确认

美团已建立 `模块 → 接口候选 → 字段 → 存储/回读状态` 目录；真实 `source_path` 不会凭空填写，仍需在已授权的真实响应中逐项确认。

影响：目录已经能约束采集顺序和字段命名，但未确认的响应路径不能当作真实字段来源。

建议：从高频真实业务开始，顺序为经营汇总、流量、订单、同行排名、广告、流失订单，再扩展搜索词、点评和房型。每次仅在真实响应验证后升级字段的 `source_path` 状态。

### 已收口：广告资源与字段事实合同

`advertisingData` 已接入统一资源定义，包含广告花费、订单金额/数、曝光、点击、ROAS 和 CTR 的保存与回读合同；默认不加入自动采集，只有明确采集到广告模块时才处理。

边界：广告的专用响应归一化与真实 `source_path` 仍需基于已授权样本确认，当前不得把目录合同表述为真实广告数据已可用。

### P1：可选模块缺字段级事实

搜索词、流量预测、流量分析、点评和房型缺少完整的字段事实定义；广告和流失订单已补齐字段事实合同。

影响：数据可能进了 `raw_data`，但下游无法稳定分辨真实值、缺失和解析失败。

建议：先补搜索词/分析，点评只保留评分、数量和标签等聚合信息，不保存点评明文。

### P2：美团广告、点评、房型缺专用归一化

这些模块目前主要依赖通用解析。接口结构变化时，可能静默漏字段。

建议：只使用已授权、脱敏的真实响应样本补专用归一化器，严禁把别人的 Cookie、Webhook 或单店脚本直接导入。

## 6. 后续实施顺序

1. 保持当前经营汇总、流量、订单、同行排名主链稳定。
2. 决定携程唯一事实存储，消除专用表与 `online_daily_data` 双口径。
3. 建立美团接口级字段目录，用真实响应逐项确认 `source_path`。
4. 用已授权真实样本确认广告的专用归一化与 `source_path`，不扩抓未授权模块。
5. 补搜索词、流量分析；点评和房型按实际使用频率后置。
6. 每新增一组字段都执行：真实接口命中 → 字段事实 → 保存 → 数据库回读 → 页面状态 → 缺失测试。
