# 推广回报与实验记录

入口：系统与工具 → 专项工具 → 酒店量化模拟 → 佣金调整与付费流量测算 → 三、推广账面回报与增量实验。

1. 选择系统酒店、平台、平台门店及观察日期。更换范围会清空当前输入，避免串用资料。
2. 写明前期、假设、分组依据、主指标、停止规则和归因窗口。没有对照时选“无可验证对照”，仍可保存计划。
3. 手工加入明细或导入JSON数组。未知成本留空，明确没有成本可填写0并提供同订单群凭据。财务凭据可从“净收与恢复”核对；先保存实验再切换页面。
4. 按需要补充前后处理/对照组间夜、可售间夜、独立样本量、观察采集时间及同期变化检查。数值来自来源，不使用AI补齐。
5. “计算当前观察”不保存；“保存新版本并回读”保存不可覆盖的版本。可从历史回读任一版本、继续编辑后另存下一版，或下载与页面相同的已保存结果。

## 三种结果

- 平台归因：退款前收入、退款、退款后收入、订单数、净归因ROAS。平台归因不是广告带来的全部新增收入。
- 账面回报：退款后归因收入减去净佣金、履约成本、其他同订单群成本和广告消耗。任一成本未知则余额未知；未纳入全店固定成本，不能称为酒店利润。
- 增量：复用可售间夜归一化双重差分。只有可验证对照、前趋势、样本门槛、完整覆盖、成熟快照、来源证据及同期变化检查均合格才返回方向性估计。估计额外减去广告消耗；始终不宣称统计显著性或承诺收益。

人工输入/导入由接口固定为 `manual_unverified`。精确回读只证明保存内容一致，不把它升级为真实OTA事实。因此当前人工入口的增量结论保持未知，并列明缺口。可信来源对接需消费完整同范围证据合同，不能通过提交一个 `verified` 字段放行。

## 导入明细合同

JSON根节点为数组，每条记录包括：

| 字段 | 口径 |
| --- | --- |
| tenant_id / system_hotel_id | 当前租户/系统酒店；手工表单缺省租户由认证服务填入，显式不匹配拒绝 |
| platform / platform_store_id | ctrip或meituan及对应平台门店；不允许混店、竞品或去哪儿替代 |
| campaign_id | 平台活动ID；所选活动必须采用单触点互斥归因 |
| period_start / period_end | 明细覆盖日期，需落在当前观察范围 |
| snapshot_kind | daily_total（日总量）或cumulative_snapshot（累计快照） |
| attribution_window_days | 报表归因窗口，必须与计划一致 |
| currency / amount_unit / attribution_model | 固定CNY / yuan / single_touch |
| collected_at | 含时区采集时间，如 `2026-09-08T10:00:00+08:00`；不能晚于观察截至日 |
| source_ref | 可核对的平台报表/导出凭据编号；不要填写凭证或原始认证响应 |
| cost_source_ref | 同归因订单群的财务/结算成本凭据编号；有成本数值时必填 |
| spend / attributed_revenue / refunds | 消耗、退款前归因收入、同群退款，人民币元，最多2位小数 |
| commission / fulfillment_cost / other_cost | 同订单群退款后的净佣金、履约成本、其他成本；不可直接填全店月度成本 |
| attributed_orders / refunded_orders | 归因订单及全额退款订单，非负整数；部分退款金额进入refunds，不能重复扣订单 |

未知金额/订单用 `null`。0是明确存在的零值。金额或订单为负、退款超过同群收入/订单、单位不一致、缺窗口或范围冲突时拒绝，修正后可重试。

同活动、同起始日期的累计快照取最新采集版本，累计期扩展不重复相加。相同采集时刻内容冲突、累计期倒退、日记录与累计期重叠均拒绝。逐活动核对日期覆盖，其他活动的数据不能填补本活动缺日；不足时显示“非全期间金额”。日历到期仍需要归因和分组观察均有窗口结束后的快照。

## 接口与边界

- `POST /api/promotion-experiments/preview`：同酒店有查看权可计算人工观察。
- `POST /api/promotion-experiments/versions`：需 `operation.execute`，提交实验标识、幂等键、预期版本、范围及输入。
- `GET /api/promotion-experiments/versions`：当前完整范围的最近50版，超出明确返回truncated。
- `GET /api/promotion-experiments/versions/:id`：完整范围+ID精确读取，校验内容摘要。

API统一 `code/message/data`，写入失败不显示成功，旧版本冲突返回409。更换酒店/平台门店/日期、编辑输入或卸载页面后，迟到请求不能更新当前结果；重复提交不会覆盖已有版本。

新表迁移须由集成/发布流程执行。本地SQLite和隔离浏览器验证不证明正式MySQL迁移、真实账号权限、OTA来源、现场实验或经营效果。
