# 携程 / 美团：100 条基础数据规则与修复审查

日期：2026-09-04。对象：宿析OS携程、美团采集、保存、历史查询、展示及直接数据消费者。

这些是本次工程验收规则，不冒充平台官方政策。每条规则必须用代码、执行测试或实际页面证据判定；不能因为列了规则就算通过。范围不含 PMS 写入、OTA 操作、上线、财务审计和全酒店收益认定。

本轮最新优先级：用户明确“主要考虑功能性问题”。验收以能找到已存历史、按酒店/日期查询、正确回显、明确报错并恢复为主；旧字段单位与退款原始事件的3项资料缺口继续披露，不作为正常历史功能的停工门槛。下文保留全部100条判定，不声称所有真实经营数据均已核验。

同日后续用户授权的高优先级功能审查另见[OTA P0/P1专项修复](ota-p0-p1-functional-audit-20260904.md)：3个新P1涉及酒店查看权限、请求归属与测试数据污染；不增加或重编号原100条规则。

## 一、身份与范围（R001–R010）

1. **R001** 每条事实绑定明确的内部酒店，不能靠名称猜所属酒店。
2. **R002** 租户边界由服务端校验，客户端传入酒店号不能扩大权限。
3. **R003** 平台门店 ID 与内部酒店 ID 分开保存和解释。
4. **R004** 携程与美团事实不可相互填空或串平台展示。
5. **R005** 本店、竞争酒店、竞争圈平均值必须是不同角色。
6. **R006** 竞争酒店不能被推断成采集账号绑定的本店。
7. **R007** 酒店改名不应导致原有历史丢失或另建事实身份。
8. **R008** 已停用采集配置不应阻止有权限用户查询已保存历史。
9. **R009** 切换酒店后，旧酒店的异步响应不能覆盖新酒店视图。
10. **R010** OTA 数值只能声称对应渠道表现，不能自动声称全酒店业绩。

## 二、日期与时间（R011–R020）

11. **R011** 业务日期与采集时间分别保存、分别展示。
12. **R012** 日期必须是真实日历日期，不能接受 2 月 30 日等值。
13. **R013** 非法日期不能静默变成今天、最新或全部数据。
14. **R014** 日期范围开始日不得晚于结束日。
15. **R015** 日界统一按 Asia/Shanghai，不能用 UTC 截日替代。
16. **R016** 下单日、入住日、离店日、结算日不可混用。
17. **R017** 实时快照、历史日终、累计周期和未来预测必须区分。
18. **R018** 过去某日的实时快照不能冒充该日最终业绩。
19. **R019** 历史回放不能使用观察日期之后产生的预测快照。
20. **R020** 查询某日缺数据时应明确缺失，不自动换成最近有数的一天。

## 三、采集结果（R021–R030）

21. **R021** HTTP 成功只代表传输成功，不代表业务数据采集成功。
22. **R022** 登录页、验证码页、错误 HTML 不能当成数据 JSON。
23. **R023** 任务运行成功、字段完整、保存成功、回读成功分别记录。
24. **R024** 部分模块成功不能把整批缺失模块标记为成功。
25. **R025** 空响应要区分确认为空、未返回、解析失败、权限失败。
26. **R026** 采集必须核对响应中的平台门店与请求目标。
27. **R027** 采集必须核对响应日期与请求业务日期。
28. **R028** 同一批次有稳定任务/来源标识，可追溯到保存记录。
29. **R029** 重试有界，遇限流不无限循环、不制造重复运行。
30. **R030** 当前账号失效不能抹去先前已验证事实的有效性。

## 四、保存与版本（R031–R040）

31. **R031** 数据成功必须在持久化之后报告。
32. **R032** 保存回读必须比较酒店、平台、日期、类型和实际值。
33. **R033** 重复投递同一事件应幂等，不重复累计业绩。
34. **R034** 唯一键包含真实业务粒度，不仅是酒店加日期。
35. **R035** 同一天多次实时快照应保留其可辨识版本。
36. **R036** 不同观察时点的未来预测应保留各自版本。
37. **R037** 不完整的新批次不能借旧批次字段拼成完整新事实。
38. **R038** 更新空值不能保留旧数字而假装本轮采到了。
39. **R039** 事务失败不得留下伪装为完整的一半记录。
40. **R040** 回读验证标记只能作用于实际验证的那一版本。

## 五、历史可回溯（R041–R050）

41. **R041** 正常保存的数据能按酒店、平台、业务日期重新查询。
42. **R042** 历史查询不能依赖重新登录 OTA 或重新采集。
43. **R043** 历史列表展示真实覆盖日期，而非暗示每天都有数据。
44. **R044** 已保存历史与可重新向平台补采的范围明确区分。
45. **R045** 历史查询须区分日终数据与当日过程快照。
46. **R046** 分页先按完整事实组分组，不能把同一批次拆散。
47. **R047** 总数、分页、筛选和摘要必须基于同一查询范围。
48. **R048** 查询失败与“没有历史”不能显示成同一种空状态。
49. **R049** 历史详情权限不应弱于历史列表权限。
50. **R050** 历史比较有准确的基期，不得拿最近一次采集冒充昨日。

## 六、空值与质量（R051–R060）

51. **R051** 缺失值不等于 0，展示和计算都必须保留区别。
52. **R052** 来源明确返回的真实 0 不得被误判成缺失。
53. **R053** 文本占位符、空串、NaN、无穷值不能转成有效数字。
54. **R054** 原始值、标准值、推导值的来源路径应可区分。
55. **R055** 数据可信状态与查询请求状态分别表达。
56. **R056** 陈旧数据可以参考，但必须标时间和陈旧状态。
57. **R057** 人工导入、自动采集、模拟数据不混淆。
58. **R058** 异常值应提示核对，不擅自截断、归零或改成正常值。
59. **R059** 同一批次有冲突证据时不得只挑有利数据。
60. **R060** 来源证据不足的数据不能直接放行给自动经营决策。

## 七、金额与数量（R061–R070）

61. **R061** 金额保留币种和元/分单位，不能隐式放大 100 倍。
62. **R062** 订单金额、房费、实付、退款、结算、净收入分别定义。
63. **R063** 订单数、间夜数、入住人数不是同一个指标。
64. **R064** 销售均价使用同范围销售额除销售间夜。
65. **R065** ADR 的房费和间夜须同口径，不用订单实付随意替代。
66. **R066** 缺房量分母时不能计算出租率和 RevPAR。
67. **R067** 周月均价用总金额/总间夜，不简单平均每日均价。
68. **R068** 分母为 0 或缺失时，比率应不可计算而非默认为 0。
69. **R069** 退款和取消保留状态及归属日期，不能反复冲减。
70. **R070** 汇总不能将周期总量与该周期每日数据重复相加。

## 八、流量、排名与比较（R071–R080）

71. **R071** PV 次数与 UV 人数不可互换。
72. **R072** 浏览、填单、提交、支付各环节的事件定义分别保留。
73. **R073** 转化率的分子分母必须同店、同平台、同日和同粒度。
74. **R074** 0–1 比例与 0–100 百分数必须明确单位。
75. **R075** 多日 UV 不能直接相加后声称为跨日去重人数。
76. **R076** 多日转化率不能简单平均每日百分比。
77. **R077** 排名必须保留榜单、竞争范围和日期，排名不是销量。
78. **R078** 竞争圈均值不能当成某个具体竞争酒店数值。
79. **R079** 竞品房价比较须有房型、套餐、早餐、取消条件的可比性说明。
80. **R080** 广告归因收入不能当成广告带来的因果增量。

## 九、界面与导出（R081–R090）

81. **R081** 当前酒店、平台、日期范围在结果区可见。
82. **R082** 历史入口应该直接查询已保存数据，不以“获取”诱导重新采集。
83. **R083** 选择一个日期范围后，后端不能只接受单日而界面不说明。
84. **R084** 加载期间不能把旧范围数据标成新范围结果。
85. **R085** 错误重试不得使用旧响应标记当前查询成功。
86. **R086** 卡片、明细、图表和导出来源一致，或者明确不同粒度。
87. **R087** 导出说明全量还是当前页，并保留筛选身份。
88. **R088** 下载保留缺失标记，不将空白默认填 0。
89. **R089** 失败信息指出失败阶段和可行下一步，不笼统报“暂无数据”。
90. **R090** 页面实际运行产物必须与编辑的源码一致。

## 十、兼容、隐私与验收（R091–R100）

91. **R091** 旧数据缺新字段时明确兼容状态，不全部丢弃或全部认定可信。
92. **R092** 字段映射改变保留版本，不偷偷重写历史含义。
93. **R093** 数据修复不覆盖无关酒店、平台和日期。
94. **R094** 查询接口不暴露密码、Cookie、Token 或原始敏感响应。
95. **R095** 订单、点评详情最小化个人信息，分析无需泄露客人联系方式。
96. **R096** 回归测试使用隔离样例库，不修改真实 OTA/PMS 业务数据。
97. **R097** 关键修复先复现，再证明相同输入的行为已纠正。
98. **R098** 测试通过、页面通过、真实账号通过、上线成功分别报告。
99. **R099** 无法从现存证据恢复的旧数据必须明确缺口，不生成虚假历史。
100. **R100** 每项审查结论绑定证据；未检查、受阻、已通过不能互相代替。
