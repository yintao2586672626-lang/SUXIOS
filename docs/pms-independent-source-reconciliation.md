# PMS 独立数据源与差值判定

## 结论

订单来了 PMS 与美团云 PMS 是两个平级、独立的真实数据源。宿析OS统一的是事实合同和判定方法，不统一采集器，不合并原始记录，也不让一个来源覆盖另一个来源。

统一链路：

```text
来源自身验真 -> 保存与数据库回读 -> 标准事实映射 ->
同日期与相近采集时点 -> 同口径差值 -> 人工复核或继续使用
```

## 提取的精华

1. 优先读取登录页面自身的结构化接口，不依赖容易变化的 DOM 文案。
2. 汇总数据和房型明细必须交叉验证：
   - 已售汇总 = 房型已售合计；
   - 首页可售与房型可售差值必须显式保留；
   - 可售差值容差为 `max(2间, ceil(总房量 × 5%))`。
3. 关键公式必须用原始分子和分母重算：
   - `ADR = 同口径客房收入 ÷ 实际出租间夜`；
   - `RevPAR = 同口径客房收入 ÷ 可出租房间天数/可售房晚`；
   - `OCC = 实际出租间夜 ÷ 可出租房间天数/可售房晚 × 100%`。
   - 只有酒店、营业日、住宿范围、税费、维修/停用房和免费/自用房处理均已对齐时才计算；缺少分母时返回不可计算，不使用“总房量”或 OTA 库存替代。
4. 超售和小差值是警告证据，不应静默丢弃；超过容差才阻断该来源进入已验证状态。
5. 页面看到数字、接口返回成功和数据库存在记录，都不等于事实可用；门店、日期、字段、内部对账和数据库回读必须同时通过。

## 宿析OS的改进

原样例在小差值时直接采用首页可售数。宿析OS保留首页值与房型合计值及差值，不静默选边。

每个 PMS 还会与自己的上一条同日可信快照比较：

```text
elapsed_hours = (current.captured_at - previous.captured_at) / 3600
net_pickup = current.sold_room_nights - previous.sold_room_nights
net_pickup_per_hour = net_pickup / elapsed_hours
room_revenue_per_hour =
  (current.room_revenue - previous.room_revenue) / elapsed_hours
```

- 第一条合格快照只建立基线，不假装有增长速度。
- 失败或未验证采集保留在审计记录中，但不会成为差值基线；下一条合格采集继续寻找上一条同日已验证快照。
- `net_pickup` 只代表账面净已售间夜变化；没有累计取消证据时不称为毛预订。
- 累计房费或已售超过动态容差向下回落时，先标记 `PMS_DELTA_REVERSAL_UNKNOWN`，核对取消、退款、冲账、换房、补录和数据修订。
- 可售房量基数变化超过容差时重新建基线，不把容量变化误判成销售节奏。
- 少于5分钟标记噪声风险，超过6小时标记低可比性；仍保留原始差值，但不做强经营归因。

跨 PMS 比较另外遵守：

- 两个来源先各自完成验真，任何一个都不依赖另一个才能成立。
- 两个来源采集时间相差不超过15分钟才判定跨源差值；超过时只并列展示。
- 同口径本地诊断容差：
  - 已售间夜、可售房量基数：`max(2, ceil(较大值 × 5%))`；
  - OCC：`2` 个百分点；
  - ADR：`max(2元, 较大值 × 2%)`；
  - RevPAR：`max(2元, 较大值 × 3%)`。
- 订单来了总房费与美团云预计房费是来源定义和结算阶段尚未完全对齐的金额，只并列展示，不相减，也不直接标为实收、应收、已结算或会计收入。
- 超过跨源容差只产生“需复核”诊断，不撤销任一来源已经取得的独立真实性，也不自动选择真值。

这些容差是宿析OS本地诊断策略，不是美团云或订单来了平台规则。

## 状态合同

| 状态 | 含义 | 下游动作 |
| --- | --- | --- |
| `no_verified_source` | 两个来源都未通过自身门禁 | 阻断使用，不补默认值 |
| `single_source_verified` | 只有一个来源可用 | 可使用该来源，并保留来源身份 |
| `dual_source_time_misaligned` | 双源可用但采集时点不可比 | 并列展示，重新同刻采集 |
| `dual_source_needs_review` | 双源可用但同口径指标超差 | 人工核对后选择本次来源 |
| `dual_source_aligned` | 双源可用且同口径指标在容差内 | 任一来源可继续使用，但不得合并收入口径 |

## 业务边界

PMS 只为住宿客房经营事实提供证据。除非另有财务、餐饮、会议、商品及其他收入来源，不能把 PMS 工作台或住宿数据中心的金额扩大为全酒店总收入、利润、现金或已结算财务收入。

订单金额、夜审过房费、支付实收、应收账、平台账单、核销/结算和会计收入必须分开保存。预订确认、入住、在住、退房、平账和收款也不得互相替代；具体映射必须绑定目标 PMS、版本、营业日和当前酒店配置。
