# 宿析 OS 产品能力与宣传一致性完善

状态：**本轮本地完善与相关验收已完成；真实门店完整流程及经营效果未验证。** 日期：2026-09-08。

项目名：**宿析 OS「查清数据 → 找到重点 → 跟进结果」完善项目**。当前定位为酒店 OTA 经营分析与行动工作台。

## 目标与停止条件

把现有酒店 OTA 经营功能整理成用户能理解、找到、使用并核对的工作流程，同时使应用说明、宣传材料与当前实现一致。

本项目覆盖八项能力：渠道数据、历史记录、渠道经营分析、竞争圈、平台服务质量、广告效果数据、AI 日报、任务与复盘。商旅订单分类不作为独立商旅分析模块宣传。冻结的投资、生命周期和员工管理等能力不解冻。

完成条件：逐项核查入口与边界；修复发现的具体问题；完成相关回归、实际页面检查及可执行的本地流程演示；更新能力清单与新版海报；将真实门店/账号/后续经营效果的剩余验收单独列明。不把未验证标成不存在或已成功。

## 执行和权限

- 当前活动工作树存在并发/历史改动。本次只修改核查后的目标文件，生成产物由仓库脚本构建，保留原有改动。
- 单一主代理执行；不安装依赖、提交、推送、发布或自动批准业务动作。
- 可以复用本机现有登录态；密码/MFA 由用户在原设备完成。不得读取凭证。
- 真实门店范围尚未由用户另行指定。本轮只复用本机安全自动填充登录，查看页面已有默认选择和记录；真实采集、OTA/PMS 写入、通知发送与经营执行不由本项目说明自动授权。
- 已完成的上一轮聚焦测试只作对应旧内容证据；变化处追加验证。

## 已完成的具体优化

| 问题 | 修改与结果 |
|---|---|
| 快速切换酒店、日期或重复刷新时，旧请求可能覆盖新结果或提前清除加载状态 | 来源数据与影响因素分析共享范围失效机制，各自使用请求序号，并校验会话、页面与页面代次。旧成功、错误提示及 finally 均不能覆盖新范围。切换范围立即清除已展示结果。 |
| 前端没有核对结果对应的门店和日期 | 两个现有响应增加 `query_scope`，前端在展示前校验酒店 ID 和业务日期。缺少身份或身份不一致直接提示重新读取。聚合酒店范围显式标识为 0，这不是业务缺失数值补零。 |
| 静态辅助资源加载失败没有进入可恢复的错误处理；失败刷新仍可能留有旧数值 | 辅助资源加载进入 try/catch，刷新先清除旧值；失败提示可见并可重新读取。 |
| 空异常清单可能给人“数据正常、已可分析”的印象 | 数据缺口与异常标记分别处理；没有标记不代表数据完整。增加初次未读取状态与具体操作说明，兼容异常清单格式错误。 |
| 数据状态、复盘状态含义模糊 | 区分已有来源记录、已核验保存、部分、缺失、历史、未验证、人工导入、读取失败等状态；复盘准备状态不再称作“已形成闭环”。 |
| 宣传超出当前证据且首次使用入口不清楚 | README、登录页、来源页和新增产品说明统一定位。八项能力各有真实入口、条件及下一步；独立商旅分析从宣传中移除。 |
| 手机登录卡片被同排页脚挤窄 | 390px 宽屏幕实测卡片约 133px；修复移动布局为纵向排列后约 328px。产品说明另在 320px 和 390px 验收，品牌不再在窄屏断行。 |
| 长图内容密集、卖点和开始动作不够明确 | 新版保留酒店场景，缩小机器人，突出三步工作流、八项能力、界面示意及“先核对一家店的数据”。没有加入虚构客户案例、经营数字或提升承诺。 |
