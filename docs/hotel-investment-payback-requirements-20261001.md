# 酒店投资回本台账需求分析 v1

日期：2026-10-01（Asia/Shanghai）。交付状态：需求分析已转为本地实现；投资回本页面、资金台账、数据库保存与实际页面验收已完成。详见 [本地交付与验收记录](hotel-investment-payback-delivery-20261001.md)。尚未提交 Git 或部署线上。

## 1. 目标与首版口径

用户可以建立酒店投资项目，录入实际投入和实际收回金额，保存后重新打开核对，随时看到已收回多少、还差多少以及在指定假设下预计还需多久。

首版推荐按“本投资人实际投入 / 实际收到现金”统计。一个项目代表一组明确投资权益，可以与现有酒店关联；尚未开业或尚未录入酒店的项目也应能在所属租户内建档。项目名称不是酒店隔离或授权依据。

“回本金额”在页面上命名为“实际收回金额”，包括实际收到的分红、本金返还、押金返还、退出或转让净收款等。同一笔钱只能登记一次，转让款必须明确是否已扣除相关费用。营业额、OTA收入、账面利润、未到账的应收分红、借来的钱和估值增长不能直接作为该投资人的已收回金额。

另一种需求是“整个酒店项目的总投资 / 项目净现金流”。这种口径需要一致处理经营现金收入、经营支出、税费、融资与新增资本支出，不能与个人分红混算。本分析默认先交付投资人实收口径；若用户选择项目整体口径，应调整金额定义和录入方式后再开发。首版不自动按持股比例推算分红。

## 2. 最小使用流程

1. 在投资功能入口打开“回本台账”，点击“新建项目”。
2. 填写项目名称、投资人/主体、首次投入日期和初始实付金额；项目可以先存草稿。
3. 实际出资后录入投入；实际收到钱后录入收回记录。每次追加出资继续增加投入记录。
4. 输入“预计每月净收回金额”，系统展示当前资金缺口及预计剩余回本周期。
5. 后续补录、编辑或作废错误记录，汇总和预测同步重算，刷新页面仍能读回。

建档和手工记账不依赖OTA采集、AI模型或经营证据准入；相关经营判断仍保留现有证据要求。预测不能替代实际回款。

## 3. 首版必须包含的功能

| 功能 | 首版要求 |
|---|---|
| 项目管理 | 新建、查看、编辑、归档；按项目名称与状态查找；分别展示筹备中、经营中、已退出等业务状态 |
| 投入台账 | 初始投入、追加投入，逐笔保留实际发生日期、金额、类别、备注；计划投入单独显示 |
| 收回台账 | 逐笔录入实际收回金额；支持每月汇总录入；退款/冲回以明确类型和原因减少净收回 |
| 回本汇总 | 截至日、累计实际投入、累计净收回、未回收金额、资金回收比例、当前回收状态 |
| 周期测算 | 实际首次回本时间、预计剩余周期、预计回本月份；展示测算依据及数据完整性 |
| 修正与回显 | 保存后重新打开可读回，编辑后重算，作废保留历史；重复点击保存不重复记账 |
| 现有项目初始化 | 可一次录入历史累计投入/累计收回及其截至日；明确标记期初汇总，避免要求补齐每笔历史记录才能开始使用 |

首版币种为人民币。统一以元、两位小数保存，允许页面切换万元展示，输入处必须标明单位，不能在元与万元之间静默换算。金额不能使用二进制浮点累计造成分差。

计划投入不进入“累计实际投入”。计划总投资可作为预算字段；需要按完整计划测算时另显示“按计划投入预测”，不能沿用已实付资金回本的标题。

## 4. 必要录入项与保存规则

| 对象 | 必填或条件必填 | 可选或补充 |
|---|---|---|
| 项目 | 项目名称、投资主体、统计口径、租户归属、币种 | 关联酒店、开业日期、计划总投资、租约到期日、备注 |
| 实际投入 | 项目、实际日期、金额大于0、投入类型 | 类别：装修/设备/租赁押金/开办/追加；凭证说明 |
| 实际收回 | 项目、日期或明确的业务月份、金额、收回类型 | 分红/本金返还/押金返还/退出净收款；备注、凭证说明 |
| 退款/冲回 | 原收回记录或明确来源、日期、金额大于0、调整原因 | 用记录类型表达减少，不要求用户猜测正负号 |
| 期初汇总 | 汇总截至日、累计投入、累计净收回、来源说明 | 原始首次投入日期、历史是否完整；不能编造历史明细 |
| 预测 | 预测基准日、预计每月净收回金额、假设来源 | 用户说明；历史月均建议值在后续阶段增加 |

数值缺失与明确填0不同：首次实际投入不能为0；某月确认没有收回可登记“已核对、0元”。未填月份显示“未录入/未核对”。草稿无投入时回收比例、实际周期和预测均为待录入。

业务日期与录入时间分开保存。未来日期的资金记录必须作为计划；日期不完整时保留原粒度，仅有月份的记录不能自动补成某一天的实际收款。

首次投入日期决定全周期起点，开业日期仅作补充，用于说明筹备期；不能默认排除装修和筹备所占时间。有实际资金记录后，统计口径、投资主体、币种以及项目的租户/酒店关联不能直接切换并带走历史账目。

期初汇总与明细采用明确分界：截至日及之前已包含在期初金额内，之后录入增量。补录早期明细时必须选择核对并替换汇总或作为说明，不能再次叠加。累计已收回是汇总结果，不作为可随意覆盖的数字。

人工数据标记“人工录入，来源未独立核验”；凭证说明不自动等于财务核验。项目范围、发生日期、来源与录入/修改人必须能读回。

## 5. 计算口径

简单回收期采用现金回收口径；稳定等额现金流可用除法，不等额现金流按时间累计。此方法不考虑货币时间价值，不能单独表示完整投资收益。[OpenStax 管理会计：回收期与会计收益率](https://openstax.org/books/principles-managerial-accounting/pages/11-2-evaluate-the-payback-and-accounting-rate-of-return-in-capital-investment-decisions)。以下是本功能的具体产品规则。

所有公式使用同一项目、主体、币种和截至日内的有效实际记录。作废记录、计划记录和未来记录不参与实际汇总。

```text
累计实际投入 I = 期初累计投入 + 截至日内初始/追加实际投入之和
累计净收回 R = 期初累计净收回 + 有效实际收回之和 - 退款/冲回之和
未回收金额 U = max(I - R, 0)
资金回收比例 = R / I × 100%（仅 I > 0 时成立）
超出投入的净收回金额 = max(R - I, 0)
```

资金回收比例可以超过100%；进度条可在100%封顶，但数值与超出部分必须显示。超出投入的净收回金额不命名为会计净利润或年化ROI。

### 实际回本

- 逐日或逐月累计投入和净收回；在账目完整的情况下，首次累计净收回大于或等于当时累计投入的时间，记为“首次实际回本”。
- 同日记录按当日汇总判断，不能利用任意记录排序制造回本；只有月度数据时按月汇总，只确认回本月份。
- 周期从首次实际投入到首次回本。精确日期数据可展示天数与日历年月；月度数据仅展示月数/月份。
- 仅有期初累计余额时，若 R >= I 且余额完整，可确认“截至期初日已回本”；首次回本日和首次回本周期仍为未知。
- 账目未核对完整时展示“按已录入记录计算”，不得确认准确首次回本。需显示完整性缺口及已核对截至日。
- 回本后追加投入或发生退款，保留历史首次回本事件，当前状态重新显示“存在未回收资金”。首次回本事件按更正后的历史重算并保留变更记录。
- 未来追加投入发生前不回写过去的回收比例；它在实际发生后改变当前累计投入。计划追加投入只影响独立的计划预测。

### 预计回本

首版采用用户显式填写的未来每月净收回假设 F，不能用营业额替代。默认假设：从预测基准日起按完整月份等额收回，期间没有新增出资或额外退款。

```text
预计剩余回本月数 = U / F（仅 U > 0 且 F > 0 时成立）
完整月数 = ceil(U / F)
预计回本月份 = 预测基准日按完整月数向后推算所在月份
预计全周期 = 首次投入至基准日的已历时 + 预计剩余周期
```

显示小数月数（建议1位）以及“按整月回款需N个月”；预计回本日期只显示月份，说明是等额回款假设，不能显示为实际到账日期。基准日和假设保存成可回看的测算版本。

U = 0 且账目完整时，显示当前已收回全部已投入资金；不再把“剩余0个月”当作首次实际回本周期。F缺失时显示“待填写预计净收回”，F <= 0时显示“按当前假设无法测算有限回本周期”，不得显示0个月或永久无法回本。I缺失或实际账目有未解决缺口时，正式预测为待补齐；可展示清楚标记的试算结果。

## 6. 页面组织

建议复用现有投资功能入口，增加“回本台账”入口/页签。投资决策页原有经营证据状态只约束该页的经营判断，不阻断合法的人工资金台账。

项目列表每行展示：项目名称、投资主体、业务状态、已投入、已净收回、未回收、回收比例、预计剩余月份、截至日与数据状态。支持点击详情及直接“记投入/记收回”。不同项目的截止日不一致时，不能默默汇总为同日资金状况。

项目详情顺序：项目基本信息 → 资金汇总 → “记投入/记收回”按钮 → 测算表单与结果 → 资金明细/按月汇总。所有核心录入和结果在手机页面可操作、可回显。

首版状态：待录入、按已录入记录计算、尚未回本、当前已回本、历史已回本但当前有资金缺口、预测条件不足、读取失败、保存失败。读取失败不能显示成功空列表；保存失败保留表单内容。

## 8. 验收清单

以下金额示例仅用于验收，不是酒店经营事实；除明确列出数据缺口的用例外，假定账目已完整核对。

| 用例 | 操作/输入 | 必须得到的结果 |
|---|---|---|
| 核心算例 | 投入300万元，净收回60万元，未来每月15万元 | 回收20%，未收回240万元，预计还需16个月；不能据此给出已发生的全周期 |
| 追加投入 | 在核心算例上增加30万元实际投入 | 投入330万元，回收约18.18%，未收回270万元，预计还需18个月 |
| 小数周期 | 投入100万元，已收回65万元，预计每月10万元 | 剩余35万元，理论3.5个月；按整月回款需4个月 |
| 精确历史回本 | 2026-01-01投入100万元；2026-02-01、03-01、04-01、05-01、06-01各收回20万元 | 首次回本2026-06-01，历时5个日历月；月度记录版本只能给出回本月份 |
| 回款退款 | 投入100万元，收到60万元，实际退款10万元，未来每月10万元 | 净收回50万元，剩余50万元，预计5个月；退款原因可读回 |
| 回本后追加 | 已投入100万元且已收回100万元，随后追加20万元 | 保留历史首次回本；当前投入120万元、未收回20万元，未来每月10万元时还需2个月 |
| 期初历史 | 仅确认截至2026-09-30累计投入100万元、累计收回120万元 | 截至日已回本、超出投入20万元；首次回本日期/周期未知 |
| 缺失与0 | 一个月未录入，另一个月确认收回0元 | 前者显示缺口，后者为有效0；缺口不能补0或据此确认完整历史回本 |
| 预测不足 | F为空、0或负值 | 分别显示待输入或当前假设无法测算，绝不显示0个月 |
| 保存与更正 | 保存→刷新→重新打开→编辑/作废→再刷新 | 精确读回，汇总同步重算，作废历史保留，重试不产生重复记录 |
| 历史兼容 | 打开旧可研/模拟记录 | 保留原预测字段及来源，实际回款显示未录入；旧查询仍可用 |
| 权限与失败 | 跨租户/无酒店投资权限访问；保存/读取失败 | 服务端拒绝越权，失败状态可见，已填数据保留，不能冒充成功 |

开发验收需要覆盖保存、读回、修改、重复提交、旧数据和关键计算边界，并确认实际桌面/手机页面。当前仅完成需求和算例核对，未运行业务代码测试或页面验收。

## 9. 后续增量

首版通过后可增加：完整历史窗口的月均收回建议值、按月不等额预测、保守/基准/乐观情景、租约到期前是否能回本的算术提示、Excel导入导出、多投资人份额台账，以及符合统一现金口径的ROI/NPV/IRR。建议值必须展示窗口、缺失与确认0的处理，取得用户确认后才用于预测；一次性退出款不直接外推成持续月回款。

经营数据联动需单独核对酒店整体现金与成本范围；携程/美团渠道数据不能直接等于全酒店可用于回本的净现金。未来功能不作为手工台账首版的前置条件。
