## 已验证可见行为

公开页面把客服应答分为“关键词 -> FAQ -> 大模型”，并强调复杂动作可调用工具、敏感问题转人工、模型失败时保留人工接管。页面还展示了本地部署、知识沉淀、多端复用、定时触达和插件扩展等产品能力。

## 宿析OS本次吸收

只吸收“可信分层路由”这一项，并适配为酒店经营诊断链：

```text
真实 OTA 数据与确定性规则 -> 可追溯知识解释 -> 大模型增强 -> 人工确认
```

该路由不改变 OTA 数据口径，不新增自动写价或外部消息，不把知识或模型输出当成门店事实。缺失层必须显示为“证据不足”“未参与”“未调用”或“已降级”，不能伪造成功。

## 视觉与按钮适配

原站公开 CSS 可见的稳定模式包括：10px 按钮圆角、180ms 悬停反馈、主按钮轻阴影与 1px 上移、白底细边框次按钮、14px 卡片圆角，以及深墨文字配低饱和浅色背景。宿析OS只复用这些交互比例，不复制原站品牌色或营销页布局：Agent 页面把原站亮绿色映射为宿析OS深墨绿与香槟金，主数据区仍保持亮色高可读表面，并保留受阻、失败、未调用和人工确认的独立状态色。

## 未知与升级触发

公开页面不能证明其隐藏后台、模型算法、账号风控或客户案例数字；这些内容不进入宿析OS事实层。来源页面指纹变化，或宿析OS诊断路由字段变化时，定向复验本参考与 `AgentTest::testOtaDiagnosisDecisionRouteExposesUsedAndMissingLayersTruthfully`。
