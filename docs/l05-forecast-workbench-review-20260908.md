# L05 时点回测与定价情景：独立审查记录

新增入口位于酒店数据分析师与运营工具箱的收益页面。用户可导入明确标记为人工待核验或 synthetic 的历史版本，执行 7/14/30 天时点回测、比较周同期和最近七日均值基线，并保存和精确回放价格假设方案。

## 独立复核及修正

原前端只检查返回方案的酒店、渠道、门店和房型，未检查历史回读是否返回所请求的方案编号，也接受非布尔的回读标记或无效编号。两个新增行为测试在原实现上失败。

现要求保存响应包含有效内容编号和严格的 `readback_verified=true`；历史回读必须返回请求的同一编号。同范围另一份方案、无效编号和字符串校验标记均显示失败，不更新结果或已保存状态。有效方案仍可正常回放。

另补齐集成后启动组件包的生成，修复公共入口检查发现的过期产物。没有放宽测试或构建标准。

首次提交被规则资产钩子阻止：旧版钩子要求外层 AGENTS 中已经替换的两句旧文案。兼容当前完整交付规则及既有旧版规则，保留所有其他必需检查；不修改外层规则或跳过钩子。

新增五条路由触发了主路由文件的零增长约束。沿现有 domain 分片方式提取 Revenue AI 路由体，保留原注册顺序、URL、处理方法及外层 Auth 组；未提高文件限额。

分片注册表测试因新增文件而失败，分类为本次授权功能所需的结构基线扩展：不是路由行为违反合同，也不是可在不改变期望清单下修复的测试代码错误。仅在既有顺序中增加新分片，原有条目、旧路由指纹和鉴权断言保持不变。

首轮 GitHub CI 发现收益前端合同测试只读取主路由文件，无法看到已注册的分片。分类为测试读取缺陷：实际参数化路由顺序正确，产品不违反顺序合同，也没有变更该合同的要求。改用仓库既有分片展开读取器，原先“参数化审批路由在通用保存路由之前”的断言原样保留；先本地复现再修正。

后端 RevenueAiRouteExposureContractTest 存在同类读取缺陷，也改用既有 PHP 分片读取器；旧审批动作不可公开、新审批接口必须存在的断言原样保留。新增路由消费回归覆盖 ControllerRouteContractTest 与该测试，共 18 项通过。

本批集成创建的路由分片还漏写了 strict_types 声明，首轮 CI 的 PHP 源码合同检查正确拦截；已补齐声明并复验，未增加例外清单。

## 证据与限制

以上属于本地独立代码、自动测试及 synthetic 页面/API 证据。导入历史的可见时刻及来源尚未经真实采集链核验；当前入口明确拒绝将手工输入标为 verified。

预测对象是指定渠道、门店和房型的净入住间夜，不是全酒店入住率或不受库存约束的潜在需求。价格弹性、全周期库存和价格是假设，金额不代表因果增收。历史方案保留输入和结果，不在回读时重新计算。

真实来源适配、完整登录应用的跨任务验收、持久卷/备份、部署、真实预测表现及经营效果尚未验证。方案文件按租户、酒店、渠道、门店和房型范围存储在 runtime 下，部署前须落实持久化安排。

GitHub 推送、PR 和同提交 CI 状态另以 GitHub 实际记录为准。
