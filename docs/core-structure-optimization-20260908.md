## 4. 已执行的优化

### 四类已冻结模块停止继续产出新工作

新增 `RetiredFeatureReadOnly` 中间件，作用于战略推演、扩张测算、转让测算及可研报告，共 19 个变更接口。

- 原 POST/PUT/PATCH/DELETE 请求收到 HTTP 410，明确显示“已停用生成与执行，仅保留历史记录查询”。
- GET 历史列表和详情继续经过原鉴权及门店范围检查，原有错误也不会被包装成成功。
- 没有调用原计算、AI 生成、持久化或执行意图函数；旧客户端不再通过隐藏接口产生新推演。
- 保留 1,096 条战略推演、535 条可研、2,434 条扩张、2,115 条转让历史，合计 6,180 条。
- 没有现存来源为这四类模块的执行意图；通用执行意图入口也不接受客户端冒充这些保留来源。
- 日常运营里的 `/api/operation/strategy-simulation` 是另一条现有规则情景工具链，并非冻结的 `/api/strategy` 模块；本次保留其数据不足门禁及人工执行边界，不能将其固定规则结果理解成已校准预测。

停用依据是已有产品冻结状态、主链相关性及未形成执行闭环的事实。数据库记录时间可作为历史活动线索，但没有足够访问日志判断真实使用频率，因此没有据此删除仍有用的功能或表。

### 日常导航减少四个入口

“酒店量化模拟、开业管理总览、开业检查清单、经营成长档案”统一位于“系统与工具 → 专项工具”。日常导航继续围绕经营分析、OTA 数据采集、PMS、任务执行和复盘组织。权限仍来自原菜单定义。

四个页面均在当前管理员登录态下实际打开；量化历史可读，开业项目可读。观察到部分老量化记录未绑定门店，开业样本也存在未绑定状态；页面保持不能转执行的门禁，没有猜测绑定或补写真实项目。

### 缺数时能找到同门店历史

新增 `StoredOtaHistoryLocator`，只返回当前租户、内部门店、渠道和已完成业务日的历史日期。排除竞对、实时快照及未来在手数据。返回的是“有记录的日期”，不是“已验证经营结果”。

首页为空或读取失败时可点击历史日期，沿现有事实接口重新读取；不自动切日期，不以历史数值覆盖当前缺失。不同门店、租户、请求日期及尚在加载的旧响应不会生成快捷入口；查询失败与确实无历史分别显示。

实际检查中，首页 2026-09-07 的空状态显示同一门店 2026-05-10 的携程历史入口。点击后日期变为 2026-05-10；旧记录未通过事实核验，页面仍显示 0/31 项已验证及缺失状态，未虚构收入或入住率。随后恢复当前默认业务日期。

### 清理重复索引

`idx_online_daily_ai_trust` 和 `idx_online_daily_cloud_trust` 都是同列同顺序的非唯一索引：

`system_hotel_id, data_date, readback_verified, source, data_type`

没有业务代码按被删索引名强制查询。新增不可变迁移 `20260908_remove_duplicate_online_daily_trust_index.sql`，保留前者，删除重复后者。执行前保存表结构及聚合基线；经本次核心数据优化授权，使用迁移工具针对共享本地库的显式许可机制执行，仅在该命令期间设置环境变量，执行后恢复。

本地迁移版本由 213/213 升至 214/214，重复执行无待迁移。索引 21 → 20；OTA 行数 85,394 → 85,394；缺失内部门店和租户不匹配均保持 0。减少的是重复索引维护，不宣称已测得接口延迟提升。
