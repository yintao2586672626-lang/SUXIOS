## 二次复核

- 原排名历史功能尚未进入主线，隔离计数器直接绑定主线已有的手动请求入口，不复制历史查询功能。
- 排名和流量共用请求归属计数，覆盖取消后同酒店启动新请求、旧 HTTP 请求随后返回的情况。
- 追加复现了“请求失败后，异步恢复期间切换日期仍弹出旧错误”问题：失败回调现接收包含日期的完整查询校验，正常失败和抛出异常两条路径都不再泄漏旧提示；同一请求仍能释放自己的加载状态。
- 租约拒绝路径补充了全部身份维度、外部浏览器要求和用户浏览器关闭状态的回归。
- 所有运行产物由 `npm run build:frontend` 生成，未手工改压缩文件或版本哈希。
- 既有 SQL 已核对：两个索引都覆盖 `system_hotel_id, data_date, readback_verified, source, data_type`，无唯一约束变化。
- 提交 hook 首次拒绝了当前根规则中已被替换的旧文案。校验器现兼容已知的新旧规则版本，仍要求完整结果与诊断策略条款；没有跳过 hook 或删去鉴权、凭证、提交授权等校验。
- 同步新主线时，PR #45 已提供同等规则兼容性修复，因此最终复用主线的 `verifyOuterDeliveryPolicy`，移除了本候选中的重复实现。
- 首轮 GitHub CI 检出快照与主线路由行数差异：主线拆分后为 771 行，不能沿用快照的 773 行限制。已将路由和采集服务限制分别收紧到实际的 771、6,368 行；美团主线仍在 5,000 行目标以内，移除仅适用于开发快照的额外超额额度。原测试断言保持不变。
