# 客户失败操作修复与验收

本修改修复客户查询、配置保存和采集状态反馈中的已确认代码问题。普通账号的入口与实际模块开通范围对齐；状态读取失败明确显示未知并支持恢复；失败记录保留安全原因、阶段和请求标识，缺失数据不当作成功。

## 范围与调查依据

调查覆盖 2026-07-13 至 2026-09-07 的 36 个失败/告警分组，共 51,555 条记录：HTTP 失败 51,380 条、授权类告警 171 条、通知写入失败 4 条，涉及 12 个非管理员账号。另有 2 次错误密码登录。记录包含自动轮询、重试和关联告警，不是独立客户失败次数，也不能据此认定用户流失原因。

[完整 36 分组清单](customer-failure-remediation-20260908.csv) 保留每组数量、原因证据、本地处理、验证范围和仍需现场验收的事项。

## 实现

| 路径 | 结果与保护 |
|---|---|
| 采集进度与限流 | 状态 GET 使用独立读取额度；按 Retry-After 等待，网络失败退避，权限拒绝停止自动重试。旧会话、旧酒店和旧轮询返回不能污染当前状态；读取失败显示未知，提供手动重读。其他 AI 额度保留。 |
| 普通账号模块入口 | 登录与账号信息提供实际模块清单；菜单、页面和请求对齐开通策略，避免反复请求被拒绝模块。后台租户、角色和酒店校验保留，未修改真实开通范围。 |
| 知识库关键词查询 | 修正描述 OR LIKE 条件的 ORM 拼接，保留名称/描述匹配、清空、无结果、所有者和门店过滤。 |
| 罗盘与Profile探测 | 保留已有明确 business_date 调用；补齐概览探测的绑定 data_source_id，缺绑定先提示，不猜酒店或账号。 |
| 缺巡检结果 | 返回明确的 409 blocked、missing_patrol_snapshot、目标门店和生成巡检的下一步；保留已有结果及跨门店拒绝路径。 |
| 美团配置保存 | 区分旧凭据待迁移、元数据冲突、数据库异常，并保留安全阶段和请求编号。配置落库成功后，附加审计或刷新失败不再误报保存失败，提示重读核对；保存、事务回滚、旧配置和范围保护保留。 |
| 携程/美团采集失败 | 失败回执及审计采用原因、阶段、上游HTTP/业务码、日期、落库/回读状态允许列表，不记录上游原文或凭据。302、HTML、403、429独立分类，明确登录失败仍正确提示。 |
| 业务失败响应 | 携程主采集接住 success:false、失败 resultCode 和 Ack；失败Ack下的多条嵌套错误可识别明确登录要求。主采集根status保留原数据解析边界，success:true不能覆盖其他明确失败。 |
| 通知写入 | 区分通知创建与用户状态写入阶段，脱敏记录数据库原因；通知/日志故障不覆盖主要失败回执。本次未外发通知。 |
| 历史与合理拒绝 | 早期订单404之后已有82条无错误读取，当前路由保留。重名酒店和错误密码继续合理拒绝；不为减少错误记录取消保护。 |

- 按项目构建脚本同步模板并生成产物。源文件和产物一致性、提交暂存区检查及GitHub CI以当前提交的实际结果为准，不能用旧基线的结果替代。

测试均为本地合成/隔离环境，没有真实客户凭据、OTA/PMS写入或生产数据库操作。Git提交和主线合并不代表部署或真实业务验收。

## 仍需现场验收

1. 核对客户购买/承诺模块，再调整有权修改的真实开通范围。14个分组共2,395次模块拒绝的入口修复，不能代替为客户正确开通功能。
2. 历史门店权限51条和配置保存权限14条缺当时授权快照；按账号、租户、门店与配置归属核对，保留隔离。
3. 美团21次保存500、180次采集400中的144条、携程32次422与3次流量400等缺历史具体原因。安全诊断已补，不能声称逐笔历史根因已恢复。
4. 发布后对已授权普通账号验收门店/日期查询、状态失败与恢复、配置保存和精确回读。真实采集必须同时具备同租户、门店、平台、日期的采集结果、保存回执、历史回读和页面显示。
5. 按独立请求标识去重观察失败和业务完成情况；错误数下降不能单独证明客户任务完成或留存改善。
6. 生产发布、真实模块开通、凭据操作、真实OTA/PMS写入及外发各自遵守授权边界，本次Git交付不扩展这些权限。按既有发布机制暂存包并保留上一版本回退目标，不重复提交已保存配置。
