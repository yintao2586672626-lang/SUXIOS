## 优先级与可验收需求

### P0：核对状态随账目变化保持准确

源码发现：`InvestmentPaybackService.php:354` 修改/新增账目后调用 `touchProject`；`:687-691` 仅更新版本、操作者和时间。`InvestmentPaybackCalculator.php:120-123` 仍使用旧 `history_complete_through` 判断完整性。因此，已核对日期覆盖的实际账目被改动后，可能继续显示已核对。

这是源码定位结论，尚未在真实账务上复现或修复。建议先用独立账本复现，再修正核对状态，而非修改现有真实账务来测试。

验收：已核对至某日的项目，改动该期间实际金额、日期或有效状态后显示待重新核对；重新核对可保存并读回。范围外的未来计划及不改变实际金额的幂等重试应有明确规则；编辑、作废、删除、导入各写入入口需一致。原始核对事件保留，不伪造新的核对动作。

### P1：导入前显示重复与差异，保留原凭证

现有去重继续复用。预览增加“新增 / 与已有重复 / 疑似重复 / 待修正”，显示匹配对象、原因及新增投入/净收回的预计变化；选择排除或确认后再保存。

原凭证可在资金记录中查看，记录上传者、来源、日期和关联关系。旧记录没有凭证时显示未上传。图片无法识别、项目错误、日期不明、单位不明时继续要求修正。

验收：同一文件再次导入不重复计数；手工账再导入凭证可关联原记录；同额但不同真实收款不能自动合并；识别出的多人分红表需明确选中投资人金额列，不能把项目分红总额当成个人实收。任一失败不得留下部分正式账目。

### P1：项目比较视图

卡片与比较表可切换，保留用户手工卡片顺序。比较列为项目、累计投入、累计净收回、缺口或盈余、回本百分比、首次回本状态、最近录入收款、核对截至日。预计周期保持“假设/试算”标记，不与实际回本日期混为一列。

总览可以优先显示总投入、总净收回、未回本项目缺口及已回本项目数。缺口为逐项目正缺口之和，盈余另列，不能让一个项目的盈余掩盖另一个项目的未回本。缺金额项目和只载入部分项目时，必须显示覆盖范围。

验收：同截至日比较，按缺口或百分比排序不覆盖手工卡片顺序；搜索和分页范围清楚；缺金额与 0 元不同；统计按投资人范围和币种一致。

### P2：累计回本时间线

默认折叠，可查看实际投入和累计净收回的时间线，标出首次回本、追加投入和冲回导致重新出现缺口的节点。复用现有首次回本及 `reopened` 规则。

验收：仅使用当前项目、截至日内的实际记录；未录入月份不伪造零收款。若显示“按已录入记录累计值保持不变”，必须与“本月已核对无收款”区分；仅有月份的记录保留月份精度，期初余额不能推定历史回本日期。

### P2：受控资金性质及内部转账

保留现有三种计算方向，补充可选的结构化性质：初始投入、追加投入、分红实收、本金/保证金返还、退出净回款、收回冲回等。记录清楚收付款主体；旧自由文本类别保留，不静默重分类。

“已收款/计划/作废”和“待核对/已核对”分开：金额实际性与凭证核对是两个维度。自己账户间转账可记录但不新增回本；酒店实际支付给投资人的分红可计入。不能自动把 OTA 营业收入、酒店利润、未支付分红或估值增长当作投资人收回。

验收：资金类型保存/编辑/读回一致，旧账金额不变；内部转账只关联一次，确认前不根据文本或同额数据猜测；退款冲回与本金返还语义清楚。

## 页面组织建议

总览：四个核心指标 → 卡片/比较表切换 → 项目搜索/状态筛选。卡片突出缺口或盈余，最近录入收款与核对状态用简短次级说明。

详情：项目和记账按钮 → 回本概况 → 资金明细与凭证/核对 → 按需展开累计趋势与测算 → 项目资料与变更记录。

不增加默认必填的分类、资金账户或预测参数。核对操作与真实删除权限分开设计，保留管理员既有直接删除入口和审计，不自动替管理员确认或删除。
