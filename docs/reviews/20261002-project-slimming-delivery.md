# 项目瘦身与修复交付记录

本次交付提取“全面审查并修复项目问题”聊天中可追溯的修改，在独立目录适配 GitHub 主分支。没有把原工作区的其他任务修改整体提交。

## 交付行为

- 删除退休的战略、可行性、扩张、转让等页面片段、前端状态/函数/样式和不再调用的后台生成实现。保留量化测算及 main 已有的经营功能。
- 退休模块的公开写接口继续要求登录并返回 410；历史列表、详情、审批来源及跟踪兼容路径保留。服务层的写入口也明确拒绝，不调用数据库或模型。
- PMS 的有限大数不再因强制转整数变成 0，溢出的每小时速率返回缺失状态并可 JSON 编码。
- 正式业务页面及 body Teleport 弹窗禁用通用草稿恢复/保存；通用 helper 独立使用的旧行为仍兼容。
- 质量缺失、未知状态显示“未验证”及灰色；只有明确 ok 显示完整，真实零值保持原值。
- AI 人工复核必须具有同酒店、日期、渠道的诊断和具体动作。缺失或错范围时关闭审批和经营导入；空动作不能显示可复核。纯判断独立为小 helper，保持既有源码预算。
- 本地清理只处理明确的缓存；保护浏览器 Profile、采集证据、交接与财务恢复材料。只读审计拒绝链接及受保护目标，配置读取同样遵守边界。
- 4,000 行历史合成 QA JSONL 无损压缩，原文件与 gzip 解压内容逐字节一致，文档引用同步。该矩阵仍为历史测试材料。
- 根据实际保留功能更新验证器和测试；需要的退休 HTML 代码夹具以明确命名的 ZIP 保存，后台历史夹具为合成 JSON。前端生成资源由正式构建器产生。
