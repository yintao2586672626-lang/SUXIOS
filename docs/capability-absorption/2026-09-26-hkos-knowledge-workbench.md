## 这套产品的实际工作路径

`材料进入 Inbox → 按部门/模块归档 → 标记来源、版本、审核人、审核日期、复审日期与使用范围 → 只把有效知识投影到岗位模块 → 检索并核对出处 → AI/内容工作室生成草稿 → 人工验收、保存版本与复盘`。

界面宣传的 26 个业务模块主要是按模块筛选的知识与 SOP 参考页，不处理实时房态、订单或经营执行。14 个交付模块包含 Inbox、知识中心、图谱、项目、Agent、培训 SOP 和内容工作室。包内 10 条是虚构教学示例；行业内容包和真实酒店知识需要另外取得、审核或创建。商业版需单独授权；AI 能力还依赖本机或外部模型配置。指南明确提到六段式内容工作室的脚本主要为结构和占位提示，需要人工撰写或核对，不能视为一键成稿。

## 对宿析OS值得保留的机制

1. **知识有效期与模块投影**：一条 SOP 只有在来源、适用模块、审核、版本、复审与使用范围满足条件时，才进入岗位可见区；过期和撤销后停止新引用。可对照宿析OS现有知识中心与 `KnowledgeDecisionGateService`，检查岗位页和 AI 引用是否遵守同一状态。
2. **草稿与正式知识分层**：Inbox、虚构示例、人工未审内容、客户私有材料与正式可用 SOP 分开；Agent 产出先留草稿和出处，再由负责人晋级。宿析OS现有 `knowledge_units`/`knowledge_chunks`、知识晋级流程和 Agent 入口可承载这条链，需用真实门店 SOP 验证增量。
3. **产出可回读**：内容制作保留来源编号、版本、审核记录和失败状态；交付前看保存文件与重开结果。这一机制可用于宿析OS的培训 SOP 或运营建议解释，不能把本地审核当作对外发布许可。

最有价值的下一步候选是：选一条真实门店的 OTA 运营或收益管理 SOP，在现有宿析OS知识中心核对 `导入 → 审核 → 岗位可见 → 引用 → 到期停用`，并用一条未审核/过期材料作为反例。若现有链路已完整，不新增 HKOS 同款模块；若有明确缺口，再做最小适配。当前未获得这组门店样例和运行回读，故复现门未过，不标记为正式吸纳。
