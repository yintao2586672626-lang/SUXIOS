## GEO 统一合同

主线为：

`唯一实体建档 → 真实性与公开范围 → 信息总表 → 图库证据 → 关键词 → 蒸馏问题 → 标题与任务卡 → 酒店事实审核 + 顾问质量审核 → Gate 6 独立发布授权 → 固定问题集监测与复盘`

关键状态与边界：

- 审核状态仅使用 `APPROVE / REVISE / REJECT / PENDING`；未知资料写“待核验”。
- Gate 0–5 负责真实性、证据、关键词、问题、标题、任务卡和内容审核；Gate 6 单独负责发布、平台范围和额度消耗授权。
- 任务创建、内容发布、平台范围和扣点/预算是四个不同授权字段，默认均为未授权。
- 图片必须绑定编号、分类、版权人、公开范围、拍摄日期、核验状态和 ALT；AI效果图不得冒充现实事实图。
- 周边景点、餐厅、商场、停车场等第三方对象必须说明关系、来源、距离和核验日期。
- 模板里的 `0`、`PENDING`、`NOT_STARTED`、`待填写` 是空模板状态，不是当前酒店事实。
- AI可见度与曝光点击属于前置/内容指标；咨询、订单、ADR、RevPAR属于经营结果。没有同口径对照时不作因果声明。
- 示例包中的“悦城商务酒店”是虚构 fixture，只用于验证字段和失败保护。

## 预测架构合同

来源图给出的设计主线是：

`逐时出租率与远期预订清洗 → 只用预测日前特征 → 分星期/分时刻滚动回归 → 往年相关性门控弱先验 → 残差区间与满房概率 → 分时决策边界 → 每日误差、月度 walk-forward 和漂移监控`

吸纳时保留以下边界：

- H03 的 177 天样本外指标、斜率、完成度、相关性和阈值均为来源报告值；未提供原始数据和 `backtest.py`，不能复现精度。
- 来源明确禁止完成度比例法做点预测，并要求预测日只使用预测日前数据；这两项可作为目标酒店回测的硬门。
- H03 参数不得直接泛化到其他酒店。目标酒店必须重新做时间顺序样本外回测，并与简单基线比较。
- 图中的提价、关低价渠道、促销和开放折扣阈值不是宿析OS当前经营建议；自动动作保持 `withheld`。
- 真正接入收益链前，必须补齐系统酒店、业务日期、房量/维修房/超售/取消口径、模型版本、保存回读和人工审批。
