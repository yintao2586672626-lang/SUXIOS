# 竞争商圈报告 v1.1 与小红书工作流吸收记录

日期：2026-08-16
状态：`integrated`（已纳入本地隔离整合分支；未推送、未部署）

## 用户可见目标

把现有链路扩展为：

`已落库且可回读的携程/美团证据 -> 同一 competition bundle -> 界面版竞争商圈报告 -> 匿名化小红书待审核草稿`

验收合同：

1. 报告仍由 AI 经营日报入口生成，并随日报保存、按报告 ID 精确回读。
2. 酒店、平台、业务日期、来源状态、读取回查与字段缺口继续沿用现有真实性门槛。
3. 界面版报告只读取同一 bundle，不再次计算指标；可从已回读结果导出单文件 HTML。
4. 缺少可信证据时报告状态为 `blocked`，小红书草稿状态为 `withheld`。
5. 小红书草稿不包含酒店名、竞店名、精确经营数值或业绩承诺，只生成待人工审核内容。
6. 不调用外部模型、飞书或小红书，不自动发布，不写 OTA。
7. 界面版不是携程 30–35/70–86 页或美团 40/66+ 页商业 DOCX/HTML 交付，必须显式标记 `commercial_release_ready=false`。

## 唯一 Skill 与静态审查

13 个 `SKILL.md` 去重后为 7 棵唯一文件树：携程 core/dual/flagship/lite 与美团 flagship/lite/router。项目检查器均返回 `review_required`、`install_allowed=false`。

- 携程 core 使用 Python 标准库进行规范化与确定性计算；发布校验器可选依赖 `python-docx`。
- 美团三版脚本逐文件 SHA-256 完全一致；核心使用 Python 标准库，发布 QA 会调用本机 LibreOffice/soffice，并可选读取 `pypdf`。
- 小红书包依赖 `requests` 与 `PyYAML`，会访问 DeepSeek 和飞书 API；`run.sh` 会自动建立虚拟环境并安装依赖。
- 未执行上述包内任何脚本、安装器、网络调用或自动发布动作，也未安装依赖。
- 项目无同名 Skill，但与 `suxi-ai-report`、`suxi-ota-ops` 和 OTA 语义层功能重叠，因此只吸收合同和用户功能，不平行安装。
- 携程许可证为内部/明确授权商业使用模板；美团许可证仍含未填写的权利人和年份。原包、源码和私有提示词不得对外分发。

## 吸收的 v1.1 能力

1. 一次读取、一次计算、同一 `source_fingerprint`，界面与导出只做渲染。
2. 携程平台转化率与订单/访客重算转化率分开；美团曝光、浏览、订单、销售和入住窗口分开。
3. 单日/快照不写成趋势、因果或价格弹性；缺失分母不补 0。
4. 直接竞品、进攻标杆、流量标杆、转化标杆保持独立。
5. 动作必须保留人工确认、保护线、停止与回滚；任何 OTA 自动写入保持关闭。
6. 公开内容采用匿名化教育表达，不复制竞店名称、精确经营数值或未经验证案例。
7. 小红书输出采用 10 个标题、5 个封面、8 页图文、正文、10 个标签、3 条置顶评论和 1080×1440 做图说明；状态固定为待人工审核。

## 成功与失败样例合同

### 成功

同酒店、同日期至少一个平台达到 `quality.decision_eligible=true`：

- `report_document.status=ready_for_review`
- `report_document.render_contract.source_fingerprint` 与 bundle 一致
- `content_drafts.xiaohongshu.status=ready_for_human_review`
- `auto_publish=false`、`commercial_release_ready=false`

### 失败

来源缺失、绑定/日期/回读/关键分母不满足：

- `report_document.status=blocked`
- 数据缺口原样回显
- `content_drafts.xiaohongshu.status=withheld`
- 不输出正文、标题或执行建议

## 已实现入口

- AI 经营日报继续保存并回读同一 `competition_circle_bundle`；新增 `report_document` 和 `content_drafts.xiaohongshu`，不建立第二套指标计算。
- “结果交付件”按钮调整为“产出报告”：保留原 JSON，可信 bundle 同时导出单文件 HTML，并把匿名化小红书草稿复制到剪贴板。
- HTML 内保留业务日期、质量、来源指纹、平台分节、竞品分组、数据缺口、人工动作和商业交付边界。
- 证据不足时仍可导出阻断报告，但不会生成或复制小红书正文。

## 用户纠错：竞争圈数据是自动输入

- 生成报告时，用户只选择酒店和业务日期；是否调用 AI 是可选项，不要求手工填写分析数据。
- 系统按当前酒店和日期自动读取已保存且已回读的携程、美团竞争圈，分别显示登录、目标日、分析字段和缺口状态。
- 携程和美团两个平台都达到就绪状态后，才允许点击“生成分析报告”；缺少哪一侧就明确显示哪一侧未就绪，不用旧数据、空数组或 0 顶替。
- 删除生成前的“简版 / 旗舰版 / 双版”选择。一次生成只形成同一份可追溯分析结果；企业微信简版/旗舰版仅作为报告生成后的交付渲染方式保留。
- 以上交互由 `verify:ota-competition-report` 固化，防止生成入口退回到手工选版本或绕开双平台回读门槛。

## 用户纠错：报告入口放在竞争圈数据旁

- 携程竞争圈表格的“数据下载”左侧增加“简易版”和“旗舰版”，让报告产出入口与当前数据处于同一工具栏。
- 点击后自动带入当前系统酒店和携程表格返回的数据日期，再由正式报告接口核对同酒店、同日期的携程与美团保存/回读状态；不会只凭当前携程表格生成双平台结论。
- 简易版输出管理摘要、双平台第一矛盾、最多 3 项优先动作和最多 3 项关键缺口；旗舰版输出完整分平台分析、竞品分组、全部人工动作与数据缺口。
- 两版复用同一 `source_fingerprint` 和单次计算结果，只改变 HTML 渲染深度；旗舰版仍保留管理员权限门槛。
- 原“数据下载”图片功能保持不变，三个按钮顺序固定为“简易版 / 旗舰版 / 数据下载”。
