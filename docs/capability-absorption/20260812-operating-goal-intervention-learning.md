# 经营目标与干预学习系统：能力吸收记录

## 来源卡

- 来源类型：用户提供的产品目标 / PRD
- 接收日期：2026-08-12
- 适用模块：运营管理 → 任务执行与复盘
- 最高价值能力：用可版本化目标合同约束经营干预，并依据执行证据、同口径观察和保护指标形成三态学习结论
- 明确边界：不直接写 OTA，不把审批视为执行，不把前后相关性写成因果，不用缺失数据补成成功

## 已落地的最小闭环

1. 用户选定单个酒店，建立目标合同版本：首要目标、保护指标、经营约束、风险偏好、经营阶段、停止条件和回滚方案。
2. 用户发起新干预，或给现有执行意图绑定干预合同：动作原因、目标指标、潜在受损指标、执行前基线、观察窗口、对照、样本量和停止条件在执行前冻结。
3. 现有审批与执行证据链保持不变；干预记录只创建本地待审批任务，不触发 OTA 改价、库存或活动写入。
4. 任务执行后，用户补充同口径观察、保护指标和外部干扰；系统只保存 `supported`、`contradicted` 或 `indeterminate`。
5. 三类记录均按租户、酒店、版本和 SHA-256 内容摘要追加保存并精确回读；旧版本不覆盖。

## 判定边界

- `supported`：执行证据、观察窗口、同口径快照、回读、样本和保护指标均通过，且预先声明的目标阈值已达到。
- `contradicted`：完整证据显示目标指标反向、保护指标越界，或已触发停止条件。
- `indeterminate`：追溯性定义、未执行、缺执行证据、观察窗未结束、口径或身份不一致、回读/质量/样本不足、保护指标缺失，或存在外部干扰。
- 所有判定固定 `causality_claimed=false`，仅表达当前证据下的观察性支持或反驳。
