## 最有价值的候选机制

```text
固定酒店、业务日期和证据更新时间
→ 只展示通过事实门的少量经营信号
→ 把跨模块异动压缩成可扫读的优先列表
→ 每条异动保留来源范围、状态和时间
→ 从异动进入既有处理入口
→ 经营动作仍需人工审批与同口径结果回读
```

真正值得吸收的是“每日经营注意力压缩”，不是复制四张指标卡或深绿色侧边栏。关键失败合同是：酒店、日期、平台、指标口径或严格回读缺失时，显示 `unavailable / unverified / partial`，不补零、不计算截图式环比、不套用截图阈值，也不把 OTA 渠道信号扩大为全酒店结论。

## 与宿析OS现有入口的对照

当前本地脏工作区已经存在更严格的同题能力：

1. `今日经营看板` 已串联权威经营闭环、昨日事实、时间轴和经营编排。
2. `宿析经营闭环内核` 已直接回答“什么是真的、最重要的问题、下一步谁做什么、昨天动作有没有结果”。
3. `经营机会 / 每日一件事` 已只从严格事实、已保存问题或明确数据缺口中选一项，并支持保存为待人工审批、刷新精确回读和继续原任务。

因此本次不新增第二套看板、不导入截图示例值，也不新建指标、接口或数据库表；只在现有编排模型上增加任务级异动投影。这里的“已经存在”和“已升级”只描述当前本地工作区，不证明已提交、推送、部署或现场可用。

## 本轮有界升级

`public/home-static.js` 现在从同一批已按酒店和业务日回读的运营任务中派生两个互斥分组：

1. `今日异动速览`：只收录阻断、失败、驳回、证据缺口或已经逾期的任务。
2. `后续行动与复盘`：保留待审批、待执行、等待复盘和已复盘等正常工作流状态。

异动行继续复用原任务点击事件，进入既有任务执行与复盘入口，不在首页自动创建、审批或执行动作。只有完整 `ready` 回读且异动为零时才显示“暂无任务级异动”；`loading / refreshing / waiting / partial / refresh_failed / failed` 均显示“异动范围未确认”或“至少 N 项”，不会把数据不完整包装成经营正常。

该升级由 `tests/automation/home_operating_orchestration.test.mjs` 守卫，并纳入 `rules/business-page-contract-registry.json` 的首页经营页面回归。运行时合并包已同步到 `public/app-startup-helpers.min.js`，入口内容指纹由 `public/index.html` 更新。
