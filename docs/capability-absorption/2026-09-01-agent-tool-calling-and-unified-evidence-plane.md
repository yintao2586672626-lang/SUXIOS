## 对宿析OS的价值排序

1. **最高价值：工具调用与收据。** 模型只能从只读白名单提出检索请求；宿主校验酒店、租户、用户、平台和日期，执行后生成稳定收据。
2. **最高价值：统一证据面。** 知识片段、同酒店经营记忆和用户显式选择的本地媒体提取，用同一来源合同表达范围、质量、用途、溯源引用和内容摘要。
3. **高价值：RAG 与经营记忆。** 知识解释定义与 SOP，经营记忆提供历史经验；两者都不能替代同范围 OTA 事实。
4. **高价值：多模态线索。** 截图、音频、视频完成本机提取和精确回读后可进入问答，但仍为待人工确认的参考线索，不能独立形成经营事实或执行草案。
5. **中价值：本地模型与私有化。** 适合隐私敏感的工具选择和材料理解；模型可用性与回答质量需单独验证。
6. **当前低优先级：从头训练、轻量微调、Transformer 推导、求职与课程节奏。** 这些不直接补齐 OTA 数据到经营决策的当前闭环，暂不投入产品实现。

## 已接入的真实入口

- 入口：`AI 助手 -> 经营问答`。
- 用户可在“本机图片 / 音视频理解”中完成提取和精确回读，再显式选择最多 10 条记录绑定到下一次问答。
- API 接收 `media_evidence_ids`，但服务端仍会按同租户、同酒店、同用户和回读状态重新校验；前端传值不构成信任。
- 模型工具白名单：
  - `retrieve_knowledge`
  - `retrieve_operating_memory`
  - `retrieve_media_evidence`
- 系统输出：
  - `operating_question_tool_calling.v1`
  - `agent_tool_call_receipt.v1`
  - `operating_question_evidence_plane.v1`
  - `operating_question_unified_evidence.v1`
- 保存后按经营问题 ID 精确回读；工具收据与证据面进入内容摘要，篡改会触发回读漂移拒绝。

## 关键边界

- 当前是基于结构化 JSON 的“模型辅助工具选择”，不是供应商原生 function calling；白名单、执行和收据均由宿主控制。
- 工具全部只读，不授权 OTA/PMS 写入、调价、改库存、外发、审批或自动执行。
- 媒体只有用户显式选择才进入；原文件按现有本机提取合同处理，问答只引用保存后的提取记录和摘要。
- 知识、记忆和媒体可以解释、提示和提供线索，但经营结论仍必须引用同酒店、同平台、同日期的严格回读 OTA 事实。
- 本次只证明本地代码、自动化合同、SQLite 保存回读和本机静态资源已通过；不证明 GitHub、生产部署、真实账号登录后的现场交互、外部模型在线成功率或经营效果。
