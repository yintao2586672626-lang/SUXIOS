## 用户可完成的流程

1. 在投资回本中选择或创建项目，展开“经营测算与情景分析”。旧项目从空白开始，不默认套用清远数字。
2. 填写名称、基准日、来源、经营客房和租赁计价房间数、房价与入住率、增长、成本、租金及营建、初始现金投入与折旧。入住率和费率以百分比显示，金额以人民币元填写。
3. 点击“预览重算”，查看逐年经营结果、税前经营现金代理首次回本、期末资金缺口、首年保本线及九格敏感性。预览不写库；缺失值保持空白，不能计算时明确显示缺项。
4. 点击“保存草稿 / 测算并回读”。服务器保存输入、结果、模型版本和摘要；前端再 GET 核对项目、输入、结果、摘要、测算版本及 `readback=exact`，通过才显示成功。保存后保持测算区展开，再次打开可编辑当前版本。
5. 每个经营年的税费、融资净现金、维护资本开支、周转金变化、押金退回和残值均明确后，才提供现金调整后的情景回本；明确填0与未填写分别处理。该结果仍是人工假设，不表示股东实际收回或可分配现金。
6. CSV由同一已显示结果生成，包含项目、酒店、日期、来源SHA、模型版本、摘要、输入、年度结果及口径限制。修改输入后旧结果标记需重算，禁止导出旧结果。

每个项目保留一个当前测算，新的保存增加版本；此前快照保存在原审计事件中，界面显示版本摘要。当前没有提供历史版本恢复或多个并行情景库。

## 来源问题在功能中的处理

| 来源问题 | 系统处理 |
|---|---|
| I22 第7年租金涨8%未进入原租金公式 | 租金递增按指定经营年复合应用；样例第7年租金为2,974,320元 |
| M23合计只减一年折旧，M25虚高 | 总计从逐年结果求和，利润、折旧及现金代理分别显示 |
| M27在没有回本时可能SUM为0年，多个跨零相加 | 只查首次负转非负；未跨零返回年数null并显示“测算期内尚未回本” |
| 原现金流使用累计税前利润 | 税前现金代理=税前利润+折旧；另列逐年明确现金调整，保留完整口径限制 |
| B21营建租金未进入回收链，G13缺失 | 用户填写营建月数后，未免租的营建租金进入初始现金支出；总周期加营建月数/12 |
| B5年数编辑未联动 | 按1—30个经营年生成行数；折旧年限和统一年天数分别可编辑 |
| 单位经营成本计价口径含糊 | 明选可售间夜、已售间夜或固定年成本+已售间夜变动成本 |
| 押金、加盟费全额纳入原折旧 | 可折旧金额单列；参考示例保留原数字并显示资产分类待确认，不替用户确定会计分类 |
| 敏感性与原爬坡不同 | 明示九格采用持续入住率，覆盖成熟期爬坡；不能把中间格视为原爬坡方案 |

## 保存、权限和兼容

计算器为 `app/service/InvestmentScenarioCalculator.php`，模型版本 `investment-scenario-v1`；持久化为 `InvestmentScenarioService`，控制器为 `InvestmentScenario`。四个端点全部继承Auth且完整匹配：

- `GET /api/investment-payback/scenario/reference-example`
- `GET /api/investment-payback/projects/:id/scenario`
- `POST /api/investment-payback/projects/:id/scenario`
- `POST /api/investment-payback/projects/:id/scenario/preview`

复用现有 `investment_payback_events` 保存 `scenario_saved` 快照，并递增已有项目版本；本次没有新增数据库结构。权限复用原项目的租户、酒店和 `investment.simulate` 校验。保存不修改现金明细、已投入、已收回或未来每月净收回假设。相同当前内容重试返回unchanged；不同内容的过期版本返回409，归档项目禁止保存。损坏快照显示冲突，读取失败不会被伪装为空白成功。
