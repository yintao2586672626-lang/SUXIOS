## 已理解的采集合同

1. Playwright 使用隔离持久 Profile 打开 `http://bj.chinapms.com:8880`；账号密码由上层受保护流程临时传入，验证码由人工完成。
2. 首页读取唯一 `hotel_id` 选项，并以门店值和名称的 SHA-256 前 16 位校验门店指纹。
3. 通过同源 JSON 接口读取 PMS 营业日；营业日缺失时停止采集。
4. 分别以营业日和营业日加 14 天提交房态预测表单，解析“全部可售房、已售房、在住、预抵、预离、维修、自用、预计平均房价、预计房费收入”等中文表格指标。
5. 离店登记按每页 10 条、最多 100 页、每批 4 页抓取；原始登记号只在内存中使用，并以 HMAC 去重。
6. 找不到营业日、房态表、当前日期或实体房型时失败关闭；订单汇总不可用时只能保留 `partial`，不能补成 0 或完整成功。

## 接入时必须补齐

- 未来 14 天必须验证日期连续且数量完整，不能因两次页面可解析就标记完整。
- 分页必须验证页码或页面签名，避免服务端重复返回同一页后被误判为抓取完整。
- 被静默丢弃的无登记键、无标准日期行必须计数并触发完整度降级。
- 订单阶段的登录失效必须保留为重新认证原因，不能只压缩成普通订单失败。
- 正式接入继续复用宿析OS的酒店/租户绑定、只读采集锁、结构化保存、数据库精确回读和失败状态；不得把持久 Profile、Cookie 或验证码写入业务数据库。
