# 宿析OS 云端版任务看板

目标：让用户在网页授权后，由云端完成采集、保存分析和企业微信推送；用户只看状态与结果，不接触 Cookie、端口、CDP 或调度器。

| 任务 | 当前状态 | 交付边界 | 验收标准 |
| --- | --- | --- | --- |
| 云端 Profile 与授权状态机 | 已完成（代码验收） | 账户/租户/酒店/平台隔离，短期登录票据，状态机 | 不存 Cookie/密码；授权状态可查；未验证不能采集 |
| 云端授权用户页 | 进行中 | 授权、最近采集、缺口、重新登录入口 | 只展示中文业务状态；不暴露内部浏览器信息 |
| 云端采集任务中心 | 已完成（代码验收） | 昨日正式与今日实时任务、字段优先级、任务幂等 | 仅可采集 Profile 入队；身份/日期/字段/保存/回读不全即阻断正式消息 |
| 数据可信门禁接入 | 进行中 | 将采集回执接入现有数据保存、回读与日报门禁 | 目标日期与双渠道证据不全时只报缺口，不发经营事实 |
| 账户级企业微信推送编排 | 已完成（代码验收） | 频率、目标机器人、模板、图卡、失败提醒与幂等 | 默认预览；只有账户策略明确开启才允许正式投递 |
| 云端浏览器网关与部署 | 已完成（代码验收，待云端授权） | AES-256-GCM Profile 存储、按需浏览器、15 分钟登录窗口、本机监听、哈希回执链与 systemd | 代码契约已闭合；尚未 SSH 部署、启动浏览器或真实登录，不能称云端已上线 |
| 端到端云端验收 | 待执行 | 测试账户真实授权→采集→回读→分析→企业微信 | 每一段均有真实证据；无法取得的数据明确为缺口 |

## 当前执行命令

- `cloud-collection:dispatch`：默认预览；加 `--enqueue` 后仅入队已验证云端 Profile 的采集任务。
- `cloud-wechat-push:run`：默认预览；加 `--dispatch` 后才按账户策略走既有安全投递链路。
- `node --test tests/automation/cloud_browser_gateway_contract.test.mjs`：验证加密 Profile、回执链、本机监听和不自动启动浏览器的静态/本地契约。
- `deploy/remote-browser/verify_secure_remote_browser.sh`：仅在获得明确云端部署授权并完成安装后运行。

## 不作为完成的内容

- 没有真实云端登录、没有实际云端部署、没有真实采集回读，不能称“云端已上线”。
- 未通过可信门禁的任务不能用旧数据、0 或模拟值伪装为经营事实。
