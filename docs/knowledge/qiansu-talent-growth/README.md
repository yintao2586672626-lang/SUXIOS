## 源码结构与可复用机制

| 来源模块 | 可核对的源码行为 | 宿析OS现有落点与处置 |
| --- | --- | --- |
| `organizations`、`auth`、`journeys` | 角色、集团/酒店范围、员工阶段门与合法状态转换。 | 酒店与租户隔离沿用宿析OS现有授权；员工阶段另列候选，不迁移账号。 |
| `catalog`、`learning`、`exams`、`practice`、`cases` | 课程发布后按岗位分配；考试受先修/阶段约束；实操由导师评价；案例与学习记录形成证据。 | 宿析OS目前没有完整员工课程与考试实体，保持候选，不能由经营指标推断个人合格。 |
| `competencies`、`training-cycles`、`customer-operations`、`read-models` | 汇集证据做能力观察，低于阈值且实际被观测的维度可生成周期；任务附证据后待下周期核验。 | 店长能力档案已有案例、带教建议和复查。只对照证据门，不把员工能力分或来源阈值并入现有店长分。 |
| `document-ingestion`、`content-studio`、`candidate-research`、`knowledge-index`、`course-evolution` | 来源文件哈希去重，分段定位，生成可编辑候选，人工审核发布；课程修订保留版本与冲突保护。 | 与知识中心导入、SOP知识晋级对照；来源的片段引用/版本行为尚未在同题样例重放，保持候选。 |
| `ai`、`ai-settings` | AI 功能依赖受控配置；未配置时不可用。 | 仅保留失败状态原则；不读取或迁移任何密钥。 |
| `deploy`、`docs` | 独立应用的部署、备份和恢复步骤。 | 隔离，不执行。 |

### 重点行为合同

1. **资料到候选**：在 `document-ingestion/service.ts` 中，上传先校验类型、大小与酒店范围，并按同酒店文件哈希去重；处理依次记录解析、分析与候选状态。解析失败与分析失败分别留下失败码。候选可以修订、合并、拆分，审核后才发布。对应宿析OS的知识导入与晋级工作台。来源文件 `SHA-256 f1404579614e4ff95471620f61eade2203b1138cf46958df1b89c33439be4777`。
2. **任务证据与效果复查**：在 `training-cycles/service.ts` 和 `task-evidence.ts` 中，同员工同月先建快照，只有实际观测且低于阈值的维度才入干预；任务缺证据不能完成。全部任务完成后是“待验证”，下一周期同维度还须有实际观测才可判效果。缺前测/后测、客观资源约束与未完成任务都要显示为不同状态。两文件 `SHA-256` 分别为 `fa6d687680f819e123a3c7ee096cd535f7458edbf6ab358eb33adb596d79f0e1` 和 `136d59c8566fb4280f3c49c0ba88d02343e2ef9bbe35aa53b7ecfa2604ab4047`。
3. **版本冲突保护**：`course-evolution/service.ts` 创建修订时要求提交者提供预期当前课程 ID，发布前再核对。学习历史与来源引用保留，不能把旧课程内容原地覆盖成新版本。来源 `SHA-256 21a985e7f58a1148fc8e0e5c9d6a5f5e6b51ee16fe40e6c4d05def94c0ab5610`。

### 不直接移植的口径

- `training-cycles/service.ts` 的总体快照对未观测维度会取旧值或默认 `80`，虽然后续选弱项仅使用观测维度，整体分仍可能含填充值。宿析OS不得把它当实际员工能力或当前经营事实。
- 来源用“后测分大于前测分”判有效；它没有提供宿析OS可直接采用的最小改善幅度、样本充分性或因果归因。不能因此自动作人员奖惩、岗位适配或经营结论。
- 来源文档说 PMS、收益和企业微信尚未接入时显式失败；这是来源声明，本次未运行这些适配器。宿析OS继续使用自己的真实失败收据，不把来源声明当平台连接证明。

## 处置与本地验收

结构化处置在 [absorption-pack.json](./absorption-pack.json)：3 项 `absorption_candidate`、1 项 `store_only`、1 项 `reject_or_quarantine`。没有 `fact_ingestion`。培训周期来源机制已达到隔离服务 `reproduced`；文档处理与课程修订的来源服务仍为 `understood`。宿析本地适配功能独立验收，不能据此声称原系统全部已验证或宿析已上线。

包内三份部署契约测试在当前 Windows 环境复跑为 **12 通过、1 失败**；失败项是 `setup-contract.test.mjs` 的 Compose 密码元字符回环用例遇到 PowerShell 语法错误，不能据此断言 Linux 部署故障。来源员工学习、考试、培训周期端到端没有运行；发布说明中的类型检查与生产构建通过未在本机复核。

本次使用 [同步脚本](../../../scripts/sync_qiansu_talent_growth_knowledge.php)把 5 项处置写入本地知识中心全局参考单元 `79`。原包哈希校验、幂等回读已通过。参考门禁维持：4 条可人工检索；部署/凭证条目隔离；全部不作为决策或自动任务草案。历史版本保留。完成本地启用后的有效 `chunk_id` 为 `938–942`，首条为 `current_chunk_id=938`。

本地 health 返回 HTTP 200、status=ok，新增表迁移已完成。当前浏览器仍显示登录页。真实组件和通用编辑弹窗已在隔离样例中验收，尚不替代登录账号页面与真实酒店验收。
