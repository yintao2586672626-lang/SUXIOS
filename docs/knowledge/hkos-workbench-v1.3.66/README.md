## 可核对的发现

1. **版本不完全同步。** manifest 为 `1.3.66`，内附使用指南、操作手册自标 `1.3.60`。压缩包提供构建产物，不含 README 提到的完整开发源码及原项目测试。具体行为以本次读取或重放范围为准。
2. **原规则没有变化。** 商业快速上手、内容来源规则和 `controlled-source-policy` 片段，与上次留存的 1.3.56 副本在忽略首尾空白后完全一致。本次没有取得并对比旧版完整 `main.js`，不能将本记录当完整升级日志。
3. **手册与权限规则有冲突。** 操作手册 5.3 把删除禁止外用标记、改公开范围、延后复审日期当作显示修复；来源规则和代码却将受限、过期作为拒绝条件。本次采用“保持拒绝、核实新授权/复审后再变更”的排查法。
4. **热力不是完整历史。** `collectFacts` 以每篇当前笔记的 `modifiedDay`（缺失时 `createdDay`）分组。旧笔记更新后会从原日移到新日；这是当前文件日期投影，不能证明历史每天发生过多少次编辑。此项为源码静态证据。
5. **连续天数误计。** 对原始 `markInboxDay` 在 9 月 24 日和 27 日各调用一次，中间未记录，它返回连续 2 天。该计数没有核对相邻自然日；原作者“积压不超过 5 条”的阈值也不成为宿析规则。
6. **保存失败后不再重试。** 原始 `flush` 在写入之前清除 `dirty`；合成内存写入器抛错后，再次 `flush` 没有重新写入。两次 flush 均返回 false，写入调用仅发生一次。结论限定于同步抛错路径，不冒充完整 Obsidian 持久化实测。

第 5、6 项已经用原包提取的代码片段重放，不是凭文档推断。片段执行只使用内存测试输入，没有加载插件入口、调用其更新工具或访问外部账号。来源缺陷仅记录和避免移植，本次没有修改第三方插件。
