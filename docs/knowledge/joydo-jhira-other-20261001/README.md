# JHIRA其余板块学习与承接合同

完成可见板块学习，形成6条新的参考知识和可重放规则：基础范围与证据就绪、债务服务、目标回本与合同余量、OTA观察与竞对可比性、报告快照与复核、GEO可见度证据。资料已按独立来源版本入库回读；均为`reference_only / absorption_candidate`。正式功能未吸纳，当前酒店事实、源站非零融资与真实采集未验证。

## 1. 基础信息：描述、假设和事实分别进入模型

区位四级、商圈标签、酒店类型、客源、渠道和销售时段可以帮助组织问题，不能凭标签推定真实需求份额、价格水平或成交效果。每个字段需有酒店/项目绑定、采集日期、来源与质量，人工填报也要明确人工假设。表单78%完整，不等于78%事实被验证；模块已启用不等于已经接通真实数据。

联动状态应至少分为未选择、选择但缺输入、输入为假设、证据待核对、同范围证据可用。报告按已选择模块说明覆盖与缺口，禁止把未选择模块计为已完成，或把全未选择的空集合显示成全部就绪。模型初稿可以输出假设与缺口，正式专项交付需额外证据。

来源销售时段12小时描述有效订房窗口，不自动把50房×30天的可售间夜减半，也不表示入住率上限变成50%。日间房、整晚房、停用房和营业日边界需另有业务定义。客源标签用于调研问题，不填成未经核验的客源构成比例。

宿析唯一承接入口：`FeasibilityReportService::normalizeInput()`及现有可研表单。已有区位/客群文本和保存路径；增量候选是结构化客源、时段、来源日期和证据质量，避免平行基础信息库。本次只读源码，未新增表单或保存这些来源示例为酒店事实。

## 2. 融资：利润为正不代表每期有钱偿债

债务输入最少包含来源、借款主体/项目、提款和起息时间、未偿本金、利率类型、期限、还本方式、费用范围。等额本金、等额本息、先息后本的逐期现金不同；期末大额本金不能被全年均值掩盖。提前还款、展期和浮动利率需另有合同证据，本次不代替合同解释。

每期保持`期初本金−偿还本金=期末本金`，债务服务为约定范围的本金+利息+其他偿债费用；贷款流入不属于经营收入。本金还款是现金流，利息与费用的利润归属和现金扣除要明确，不能在费用与融资调整中扣两次。资金来源覆盖与投资用途另做同范围核对，不自动补足差额。

DSCR的本地示意口径为同期间可用于偿债的现金/约定债务服务；不得用已扣完同一债务服务的剩余现金再做分子，也不能把任何“利润”字段自动视为完整分子。没有债务且费用明确为零时为不适用；债务金额/还款方式未知时为缺输入。按月核对低谷现金和期末本金，年度DSCR不能替代流动性路径。[S&P项目融资比率定义参考](https://www.spglobal.com/ratings/en/regulatory/article/-/view/sourceId/11884994/revId/1)

自编回放以60万元、名义年利率12%、12个月、按月计息为例，全部是合成输入：等额本金全年债务服务63.9万元，先息后本67.2万元；两者本金均归零，但后者最后一期集中归还60万元。该差异说明为什么必须保留还本方式和时点，不是借款建议、银行阈值或源站算法。回放用整数分逐期结算并将尾差留在最后一期。

宿析承接现有`InvestmentScenarioCalculator.cash_adjustments.financing_net_cash`，候选债务计划只生成同期间融资流入减本金/利息/费用的调整。现有情景利润未单列融资利息，接入时明确费用包含范围；不能仅凭字段名当完整会计利润。缺完整现金调整仍保持null。真实投资者出资和收回继续走投资资金台账。

来源样例为零借款，不能验证非零还款算法。可见自有资金与投资用途覆盖差异仅作输入核对，不能替代资金到账事实。

## 3. 回本与合同：期限目标、剩余投资和可实现性分开

先确认投资额是否同一投资者/项目范围，已收回是实际现金台账还是情景经营现金；经营利润不能自行冲减未回收投资。以剩余金额I、同期间净价p、单位变动v、固定F、债务现金D和目标月数T，在稳定简化条件下，目标入住率为`(F+D+I/T)/(A×(p−v))`。

目标入住率超过100%只标指定期限不可达；不能否定更长时期回本。贡献非正时没有此模型下有效解，恒定净现金非正时不输出正有限剩余回本期。已经收回的已知剩余额0可显示剩余回本0，持续亏损仍需独立披露。每个目标同时显示条件、单位、所需价格/入住率与未覆盖项，不把情景压力标签变成经营事实。

合同余量应使用同一基准日下的**真实剩余合同期限−同口径剩余回本期限**，缺合同日期或无有效回本时为未知。正、零、负各有不同含义；可研租期、测算年数都不能自动当剩余合同。续租未批准不能加进余量，合同到期、装修期、停业期等需实际日期证据。

源站滑块上限与手工价格上限分开，保留“手工输入是权威值、滑块只是辅助”的交互原则；本次未修改价格或实测超上限值。宿析承接现有情景输入/快照与回本输出，候选只增加目标期限和合同基准字段，不再造计算器。

## 4. OTA：观察场景比不透明分数更有价值

一条排名观察应带酒店绑定、平台、实际搜索词、时间、入住/离店日期、定位方式、登录与设备、筛选/排序、广告位置及结果页范围。区间排名保留区间，不拿中点冒充精确排名；“未看到”还需要已检查的结果范围，不等于不存在。首页判定需要当次页面容量，不能按统一固定名次阈值套所有平台。

列表、详情、预订可分别组织：展示和房型信息、点评与政策、价格库存和取消确认条件等。填写进度只衡量记录覆盖，不是质量分；平台未诊断不写0分。对比竞店必须同平台、可比观察窗口、入住日期、关键词和筛选范围，保留各次真实观察时间而不要求同一秒；字段未知时保留不可比，不能跨渠道用同一权重排名。

证据需要截图/来源记录及时间，人工填写本身不变成平台后台事实。排名不是曝光，曝光不是点击，点击不是订单；转化率需同范围分子分母，不由排名推算。AI模板或成功生成文字不证明模型调用成功、实时采集、人工复核或经营因果。任何建议仍通过宿析既有授权链。

来源台账写入禁用，采集/审核/锁定处于设计阶段。本次未生成诊断、写台账、上传、导出或访问OTA后台。宿析唯一承接是携程经营雷达的来源证据维度与保存摘要，不把来源表单分数当携程官方评分，也不将携程结构扩大为美团同口径事实。回放实际调用现有雷达纯构建方法，验证缺证、历史和平台错配边界。

## 5. 报告：复核是同版本证据状态，不是一个百分比

报告应冻结酒店/项目、业务期间、输入摘要、计算模型、启用模块、来源与缺口、受众和模板版本。预览可带未核验假设；正式交付必须另检查范围、所需证据、人工复核、版本新鲜度及导出权限。改输入后旧复核/预览失效，不能仍用旧报告“已通过”的标记。

HTML/Word/PDF/PPTX等格式应消费同一冻结规格，但共享模板不能证明文件一致。实际导出后需核查字节/摘要、关键数值与日期、缺口、受众、字体/分页等；导出按钮禁用只证明当前前端状态，不证明服务端鉴权或跨酒店拒绝。机器校验、人工复核、投决批准和经营执行分别记录。

本轮源站3/6与上一轮2/6是时间快照，未验证变化原因及六项定义。宿析已有可研8项准备度、报告呈现规格的人工复核pending与不可变制品入口；不能把源站6项套成宿析8项，也不能宣称pending已有正式导出禁用。候选是在现有规格和权限上补分阶段交付合同，复用现有导出器。

具体承接：可研`buildFeasibilityReadiness()`负责投前证据与阶段；`AiDailyReportPresentationSpecService`和制品服务负责经营报告规格与产物。两者服务不同报告，报告只能引用选定模型的已保存数值，不能混合不同模型的利润口径。来源规则风险分值、固定5年/3年边界及价格建议不进入默认经营规则。

## 6. GEO：提及、引用、事实一致和转化逐级测量

公开页提供关键词扩展问题、覆盖多个模型、监控变化的产品思路；没有给出可重放算法、实际测量或优化因果。保留问题集组织方式：品牌事实问答、位置设施与政策、旅行动机和场景问题，逐项关联可核实的酒店知识。不能向外部模型发送账号或私有客户/经营数据。

观察要保留问题版本、模型/服务版本、时间、地区、搜索/联网状态、响应引用和保留依据。分别记录品牌提及、有效来源引用、事实一致性和动作/成交；缺响应时指标未知，明确未提及才记零。模型回答序号不等于OTA排名，单次回答不证明长期可见度，提及增加不证明订单增长。
