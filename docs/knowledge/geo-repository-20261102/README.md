## 结论与取舍

最值得借鉴的是“有归属和适用条件的知识 → 有依据的策略选择 → 可恢复的执行流程”。它把来源、候选ID、事实回填、失效条件和版本链变成显式合同。营销内容与酒店经营的目标不同，内容机会分和酒店收益分不能互换。

本轮定向阅读确认：宿析OS当前源码已有知识使用门、酒店/用户/平台过滤、证据投影、事项排序、租约保留和行动来源摘要。应吸收增量，避免重建相似功能。源码存在不代表实际登录页面、数据库、部署或业务效果已验收。

首选后续候选：**经营问答中可核对的引用命中、排除原因与缺口说明**。现有检索返回来源、质量、引用、分数与排除计数，但本轮没有验证实际页面的逐候选原因是否足够，故价值门仍待验证；不能据此认定当前产品有确定缺陷。

## 1. 知识关系：先适用，再引用

来源：[知识关联说明](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/docs/07-knowledge-relations.md)、[匹配源码](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/src/lib/brain-matching.ts)。

机制：问题+客户/场景 → 主业务与协同业务 → 有有效证明的优势 → 适用案例 → 关联方法。逐步保留主体与理由。排除场景、客户不匹配、证明失效可以阻断；关键词与关系命中不能覆盖排除条件。

资料沿门店→品牌→集团取得，集团经验继续标注集团归属，不能横向借用兄弟店私有知识。祖先遍历本身不证明外层请求已经鉴权。

已重放：经营问题匹配托管+OTA及相应案例/方法；排除采购场景；客户限制优先于精确问题命中；缺证明时剔除优势；不把通用优势关联的无关筹建案例带入；未知问题返回待补充。

**限制已实测：“并不打算筹建”仍触发筹建需求。** 它依赖有限否定词表与字面匹配，不能称通用语义理解，不能据此直接发起经营动作。

宿析OS承接：`OperatingQuestionKnowledgeRetrievalService`、`KnowledgeDecisionGateService`。优先学习排除原因解释，不机械移植企业实体树和全部规则。

## 2. 策略：模型选ID，服务器回填事实

来源：[策略流程](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/docs/09-brain-strategy.md)、[选择校验与回填](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/src/lib/strategy-plan.ts)。

机制：同范围知识快照 → 最小候选投影 → 约定ID输出 → 去重、范围和必需关联校验 → 从快照回填名称、数值、主体和来源。调用结束再次核对知识指纹，变化则拒绝过期结果；规则预览与真实模型模式分开。

已重放合法选择、伪造/重复ID、遗漏核心业务、事实数值改变后的回填，以及策略不携带旧正文提纲。合成证明从3改4后回填同步变化；不代表外部事实或数据库更新已验证。

引用合法不等于事实真实。源 `source_validated=true` 只表示候选与快照校验，不等于携程/美团酒店绑定、日期、字段口径、质量、保存和真实回读通过。

宿析OS已有 `OperatingQuestionAiAnswerService`、`OperatingQuestionUnifiedEvidenceService` 的证据投影。没有当前/候选同题质量比较，保持候选。

## 4. 评分：可解释的内容优先级，不是市场事实

来源：[当前评分函数](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/src/lib/opportunity-scoring.ts)、[评分说明](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/docs/11-geo-opportunities.md)。

当前权重：商业意图30、企业匹配30、GEO回答机会20、内容资产20。模型提供意图和引用，服务器计算得分。等级S≥85、A≥70、B≥50、其他C；本轮只运行等级边界函数，没有运行完整机会评分和保存链。

来源明确 `market_data=not_connected`，没有搜索量、竞品排名和AI平台实测。它评估企业内容生产价值，不能叫真实曝光、AI排名概率、订单增量或ROI。

旧 `docs/05-content-engine.md` 仍为25/20/20/15/10/10，后续文档与源码已经不同。必须锁定算法版本，不能混用。宿析OS `DailyOneThingService` 使用影响、紧迫性、证据强度与执行成本；没有证据支持覆盖为营销权重。

## 5. 队列：持久保存等待、进度和恢复

来源：[队列合同与验收边界](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/docs/13-ai-task-queue.md)、[队列源码](https://github.com/lzy27272/GEO/blob/ac07b6b6a79a6a3a1c489866ec2959d8d1b778a7/src/lib/ai-task-queue.ts)。

机制：候选生成与逐条评分分阶段，批次和单条状态分开；短事务领取与租约令牌；网络请求期间不持长事务；保留成功项；429按提供方时间和本地退避中较晚者持久等待；计费错误不盲目重试；每次请求单独记录阶段、编号、用量、耗时与重试。

已重放来源断言中的秒数、HTTP日期、复合重置窗口、长于一天的等待、无效响应头、5/20/300秒退避和纯计数函数。未验证数据库领取、续租、跨进程接管或真实429。

| 源行为 | 借鉴时的必要区分 |
|---|---|
| `taskCounts([], true)` 返回20失败，已离线复现 | 计划数、已生成数、已评分数、实际失败样本数、未处理数分开 |
| 请求日志success之后才验证20条与来源 | 请求成功、结构有效、证据有效、保存成功分层 |
| 默认worker只通过配置工作空间取得上下文 | 不当作通用多租户消费者 |
| 外部请求已返回、本地未提交仍可能重试 | 租约恢复不保证外部API恰好一次 |

五类各4条是源企业营销问题规划，不应强迫一间酒店凑齐20个经营事项。全新批次通常1次生成+20次评分，重试额外计数；不是全流程只调用一次。文本规范化去重也不是语义去重。

宿析OS已有 `AiEvaluationRunService` 租约保留和 `CloudThreeSourceCollectionQueueService` 等队列。本轮没有复现当前用户故障，保留方法，不新增另一套队列。
