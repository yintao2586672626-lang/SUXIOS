# 前台采集身份、恢复水位与最小证据合同

来源：用户提供的 `hotel-ops-h5-no-data-20260730-155031.zip`、`使用手册.md`、`部署手册.md`。文件指纹见同目录 source-manifest.json。包内 package.json 声称 0.6.0；包名日期 20260730 不是经营日期或已验证发布版本。结论仅供技术方法参考，不是当前门店事实、安装指令或执行授权。

## 可复用机制

角色链：系统/商户/门店管理员创建平台绑定，前台人员人工登录并核对平台 HotelID/POI ID，小助手采集，运营查看来源状态与需要人工确认的线索。激活资格与门店平台绑定身份应分开，不能把“机器在线”当成“平台身份正确”或“采集成功”。使用手册 L54-100 明确了此任务路径。

输入：系统门店、平台、已确认的平台门店 ID、最近身份观测时间、指定业务日期与任务水位。动作：先验证平台及门店 ID；缺预期身份为 unverified，缺实际观测为 waiting，权威观测不一致为 account_changed，匹配但时间过期为 stale，匹配且新鲜才为 matched。美团 runtime_identity_probe 在源码中被视为非权威，不一致先 waiting。输出须同时保留身份判定、采集执行、内容验证、保存与回读状态。

直接出处：`server/platformIdentity.js:L1-27`；本轮用原函数重放了 7 个固定时钟合成样例，含缺身份、缺观测、匹配、换账号、过期、未来时刻、非权威不一致。源码的一小时阈值和一分钟未来容差只是来源实现值，不设为宿析默认规则。

恢复：使用手册 L102-106、L174-180 描述断网/停机后按最近水位补采关键缺口，不能宣称补采全部历史。迁移时应保存成功确认水位，逐门店/平台/任务/日期记录缺口；任务已领取、已执行、已保存、已回读分开。水位恢复本轮只核对手册与相关文档，未启动采集器或验证现场补采。

最小证据：`shared/orderEvidenceContract.js:L1-41` 使用带版本的 envelope、门店/平台、关联状态、摘要字段，拒绝顶层原始正文/HTML及指定敏感字段。已有状态 pending_im、pending_on_demand、on_demand_requested、im_linked、review_linked、manual_linked 表达证据成熟过程；这些状态不等于批准经营动作。初轮重放有效 envelope、顶层原始内容拒绝、未知关联状态拒绝 3 例，与源码合同一致。

五轮自纠补充：该校验不是递归隐私或门店授权校验。`metadata.raw` 的合成嵌套字段和对象型 storeId 均能通过原函数；出处L31,L34-39，证据为 five-pass/round-2.json。后续适配须使用明确DTO白名单、严格标量身份类型、递归敏感内容边界及接收端授权。不能把3个语法样例通过扩大成整个证据链安全。

存储模式：`docs/evidence-repository-runtime.md:L11-43,L62-109` 描述归一化证据和持久化桥、范围内幂等、加密 outbox 的领取/确认/失败重试；生产环境存储失败拒绝内存回退。源码路线有 SQLite/PostgreSQL 适配器，但本轮未运行适配器、迁移、真实数据库镜像或出站同步。可以学习合同，不能据此宣布已有可靠同步。
