# 点评查单的证据门与经营指标不可用反例

来源：用户提供 H5 交付包和两份手册。静态出处与原文件指纹见 source-manifest.json；本轮重放文件及结果见 `output/absorption/20261006-hotel-deliveries/h5-replay.json`。全部输入是合成样例，未使用真实订单、客人信息、点评或平台登录态。

## 点评查单行为合同

输入：同门店、同平台的点评、订单与必要关联证据。动作：过滤时间不可能的订单，按身份、入住时间/房型及订单桥接证据分组；比较第一与第二候选，输出证据、独立证据组数量、歧义原因和下一步。匿名点评需要入住与房型证据，并有唯一高置信候选；非匿名点评需身份及订单桥接。无候选、证据不足或多个高置信候选返回候选或补采/人工确认，不强行锁定。

出处：`server/reviewMatchEngine.js:L178-318,L367-387,L547-658`；`使用手册.md:L119-141,L182-184`。源码固定权重、独立组数量及分差 20 是来源阈值，不能直接当宿析业务默认。源码声明 `ctrip-bad-review-v3`（L5），`docs/ctrip-bad-review-match-v2.md:L68` 却声明 v2；版本不一致已经保留，不能用旧文档说明当前引擎已现场验证。

“独立证据组”在这里是源码对语义类别的计数，不证明不同证据具有独立来源、统计独立或独立采集验证。来自同一订单/IM/解析路径的多项特征可能共享同一错误源；正式匹配仍需记录源、共同祖先、范围和反例，而不是只数高分组数。

可学的是“证据足够且歧义解除才定唯一，否则候选+原因+人工确认”的路径。宿析现有 `CtripReviewOrderMatchService.php:L85-251` 已有候选、原因、confidence 和渠道范围；本轮不重复建立匹配器。来源包中枚举掩码身份、恢复联系方式等路线不进入本轮知识执行能力，也不重放真实身份。

## 指标来源与缺失合同

`server/operatingOverview.js:L84-95,L98-135` 给每项指标携带 value、available、partial、coverage、source、asOf，适合采用为可读合同。订单去重按平台与订单键，取消订单排除。五轮复核已对原测试逐次计数：实际执行22个assert.equal调用并通过；此前19是文本调用点计数，不能用作实际执行数。证据为 five-pass/round-2.json 的 instrumented baseline。

本轮增加 6 个概览行为样例，其中 2 个符合严谨合同（空来源为 null/unavailable；其他门店订单排除），4 个复现了来源缺陷：

1. **仅绑定但无采集→零营收**：L257 以 binding 判断来源可用，输出 source=not_collected，但 revenue.available=true、value=0。门店绑定不是零收入证据。
2. **另一平台有点评→本平台零点评**：L241-242 使用整个门店的来源可用标记，L279 用它判断平台点评可用，缺美团点评却能显示可用的 0。渠道覆盖应分别证明。
3. **旧日期缓存→当前范围零营收**：L241 用任何历史订单认定来源可用，L243 筛选当前日期后为空，L117 把它当可用零值。缺当前范围覆盖不能靠旧数据证明为零。
4. **跨渠道转化率简单平均**：L308-314 对两个平台的比率做算术平均。合成 10% 和 1% 得到 5.5%；该数字不能代表酒店整体转化。即便分母加权也须先证明同日期、同事件定义、可加的分子分母与覆盖，不在本轮采用任何替代经营值。

源码 isStale 在部分输出中提示陈旧，但不会把上述假可用状态全部阻断。不能因为原有成功样例通过，就把此概览计算直接接入严格收益事实链。

五轮补充8组重放记录，确认了4个新的合同缺口（其中2个属于envelope）：金额字符串`1e3`被清洗成13；两个各自有限的大金额汇总溢出后返回value=null但available=true；嵌套raw未拒绝；storeId对象未拒绝。另验证了已知金额100、另一单缺金额时的100/partial=true/coverage=0.5是已知小计，不能被解释为完整期间总营收。概览纯函数未在此校验overviewPayloads自带的门店/日期字段，这说明调用方必须保证绑定，不证明实际应用接口已经跨店泄露。上述均限原函数合成输入。

## 本轮证据范围

共 16 个追加纯函数重放样例：概览 6（含 4 个来源合同失败）、身份 7、envelope 3；此外原有概览测试通过。`source_contract_failures=4` 是复现结果，不能被“runner执行成功”改写成来源全通过。点评匹配与相关后台只静态核对，未运行完整应用、浏览器、OTA账号、补采、真实持久化或现场效果。

处置：参考储存 `store_only`，整个候选单元 `absorption_candidate / understood`；具名指标/身份子行为已有 `reproduced` 证据，点评匹配整体只静态理解。正式吸纳要以宿析现有严格来源和范围合同验收，不复制这些缺陷或阈值。
