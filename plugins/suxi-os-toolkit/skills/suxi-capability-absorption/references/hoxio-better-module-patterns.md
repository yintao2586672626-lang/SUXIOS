# Hoxio 优胜板块与宿析OS吸收清单

## 结论

Hoxio 不是整体能力优于宿析OS。当前证据支持的结论是：

- Hoxio 在信息架构、自助入口、状态卡片、短操作路径和经营数字的视觉层级上更成熟。
- 宿析OS在 OTA 来源边界、保存回读、数据质量、AI 决策门禁和人工复盘上已有更严格的底座。
- 吸收原则是“复用宿析真实数据链，学习 Hoxio 的用户路径与状态表达”，不复制未知后台、不另造平行采集链路。

本文件是 Hoxio 来源的统一产品模式索引。专项业务口径仍以文末链接的 OTA reference 和 eval 为准，不在这里复制第二套定义。

## 本轮重点：订单流失/流入对照

### 可吸收的页面合同

```text
同一门店 + 同一平台 + 同一期间
→ 流失与流入分别采集
→ 两侧分别保存、回读并标记状态
→ 订单数 / 间夜 / 金额同单位对照
→ 流向酒店与来源酒店 Top N
→ 房型集中度
→ 待验证原因假设
→ 责任人、截止时间和下一周期复盘
```

### “哪些客人”的正确表达

产品应写成：

- “订单流向哪些竞对”
- “订单从哪些竞对流入本店”

默认只展示脱敏聚合的酒店、房型、订单数、间夜和金额。平台页面可见的浏览与下单归因不授权宿析反向识别姓名、手机号、证件号、订单号或跨设备身份。

### 数据边界

- 这是美团 OTA 渠道内的授权归因，不是全酒店客户迁移。
- 流向关系说明“平台归因到哪里”，不说明“为什么选择”。
- 价格、评分、排名、房型权益和库存只能进入待验证原因假设。
- 两侧都成功、保存并按相同范围回读，才是 `complete`。
- 单侧成功是 `partial`；缺数据、请求失败和平台明确返回真实 `0` 必须分开。

权威口径见 [美团订单流失/流入归因口径](../../suxi-ota-ops/references/meituan-order-flow-attribution.md)。

## 可复用的横向产品模式

### 1. 一屏回答四个问题

每个经营工作区优先同时回答：

1. 发生了什么；
2. 数据是否可信；
3. 可能是什么原因；
4. 下一步由谁做什么。

指标、证据状态和下一动作不应散落在多个技术页面。

### 2. 状态卡替代技术术语

用户需要看到“已登录 / 需重新登录 / 正在验证 / 缺绑定 / 数据过期 / 采集失败”，而不是先理解 Profile、Cookie、CDP、任务 ID 或接口名。技术证据可以展开查看，但不能成为主流程。

### 3. 异步任务有完整生命周期

可复用状态：

```text
已提交 → 排队中 → 处理中 → 等待短信/人工验证
→ 成功 / 部分成功 / 失败 / 取消 / 超时
```

用户离开页面后仍能回来读取结果；失败必须给出可恢复的下一步。

### 4. 一张卡一个主动作

一张业务卡只保留一个最主要操作，其余动作降级为次级入口。关键数字、范围、更新时间、质量和主动作应在首屏可扫读。

### 5. 行动建议必须闭环

```text
事实 → 原因假设 → 独立证据核对 → 人工动作
→ 责任人/截止时间 → 下个可比周期复盘
```

AI 不得跳过证据核对直接把相关性写成原因。

## 明确不吸收

- 不复制或猜测 Hoxio 的隐藏登录、凭证保存、短信、人机验证和自动化后台。
- 不把用户输入账号密码的前端表单当作安全实现证明；宿析继续使用门店隔离、授权 Profile 和人工验证边界。
- 不吸收“远期单互助”、代下单、代取消、刷单、补单、追价单等可能操纵 OTA 平台结果的功能。
- 不补全匿名客人的姓名、手机号、证件号、UID、头像或跨设备身份。
- 不把公开库存净下降写成竞对真实销量、订单或营收。
- 不把公开前端文案、路由或资源文件当作真实 API、保存回读、生产投递或算法正确性的证明。
- 不把 OTA 渠道数据扩大为全酒店收入、客户或经营事实。
- 不因 Hoxio 有 PMS 页面就扩张为整套 PMS 重建；只在宿析当前产品链需要时吸收单个能力。
- 不一次实现全部板块；后续仍遵守“一个主任务、一个可验收结果”。

## 黄金样例

1. 账号卡显示“携程浏览器会话已失效”，主动作是“重新登录”；不得显示“账号异常”却不给恢复入口。
2. 订单流失成功、流入失败：页面显示 `partial`，流入侧为 `-` 和失败原因；不得补 `0`。
3. 竞对库存从 10 降到 7：显示“公开库存净下降 3（推算）”；不得显示“竞对卖了 3 间”。
4. 调价计算器给出结算价：它只能作为公式试算；没有底价、库存、Pickup 和转化证据时不得自动写 OTA。
5. AI P图任务失败：保留原图、提示失败原因并允许重试；不得生成一个空结果或假成功。
6. 微信提醒显示“测试发送成功”：只能证明测试目标收到，不能写成正式群生产投递已开通。
7. 评价候选订单相似：只允许人工核对；不得通过手机号、头像或 UID 反向识别匿名客人。
